## Fixed Issues

### WR-01: Favicon validator decodes percent-escapes but not HTML character references, so entity-encoded payloads get through the RND-01 gate

**Files modified:** `src/render/asset-free.test.ts`
**Commit:** 7ccaad6
**Applied fix:** Any `&` is now rejected at both decoding layers:
- `stripProceduralIcon` rejects a literal `&` in the raw href. This is the HTML attribute layer, as the review suggested.
- `validateIconSvg` rejects `&` in the decoded SVG. This is the XML layer, and it goes beyond the review: `%26#x75;rl(...)` in the href decodes to `&#x75;rl(` in the SVG, which the SVG parser then turns into `url(`.

New negative cases:
- Two hand-built links that hide `<image href=https…>` and `<script>` behind HTML references.
- One `it.each` row with `filter='&#x75;rl(&#x23;f)'` for the XML layer.

All three were confirmed to pass with the guards disabled, so each one proves its bypass is now closed.

### WR-02: Paint check is a denylist that misses SMIL `<set>`/`<animate>`, so off-palette colors pass

**Files modified:** `src/render/asset-free.test.ts`
**Commit:** bdd0a4c
**Applied fix:** Took the review's allowlist option, not the minimum denylist one. `ICON_ELEMENTS` allows only `svg`, `rect`, `circle`, `ellipse`, `path` and `g`, matched case-sensitively. It runs as the last step of `validateIconSvg`, so the existing rows still report their more specific messages. The pattern `/<\/?([^\s/>]*)/g` makes every `<` open or close an allowed element, so comments, CDATA, doctype and processing instructions are rejected too, not skipped.

New cases:
- Negative rows for `<set>`, `<animate>`, `<animateTransform>`, `<feFlood>`, a comment and an uppercase `<RECT>`. All six were confirmed to pass with the allowlist disabled.
- A positive case showing the allowlisted `g`, `ellipse` and `path` with palette paint are still accepted.
