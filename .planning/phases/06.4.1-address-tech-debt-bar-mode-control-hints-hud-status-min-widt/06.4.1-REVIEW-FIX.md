### WR-01: A paint value holding a raw LF or CR bypasses the paint check and renders any color

**Files modified:** `src/render/asset-free.test.ts`
**Commits:** 74462cd (SVG layer), 02f6350 (href layer)
**Applied fix:** Both layers were closed, one commit each.

1. **SVG layer (74462cd).** The paint regex in `validateIconSvg` is now `/\b(fill|stroke|stop-color)\s*=\s*(?:'([^']*)'|"([^"]*)")/gi`. The value is read as `m[2] ?? m[3]`, so a value with a line break in it is matched and checked. The CSS-whitespace trim (`[ \t\n\r\f]`) now runs on LF and CR as the c11462d comment meant it to.
   - I checked the other regexes in `validateIconSvg` for the same problem with `.` and line breaks. None has it. The `ICON_FORBIDDEN` patterns, `http`, `#hex`, the element and attribute-name scans, `ICON_OPEN_TAG` and `ICON_TAG_ATTR` all use literals, `\s` or negated classes, and those already match across line breaks.
2. **Href layer (02f6350).** `ICON_HREF_CHARS` now admits `%` only as `%(?:[2-6][0-9A-Fa-f]|7[0-9A-Ea-e])`, which is printable ASCII from 0x20 to 0x7E. `%00`-`%1F` and `%7F` now fail before decoding.
   - The real favicon in `index.html` only uses the escapes `%3C`, `%3E` and `%23`, so it is still admitted. Every existing positive `iconLink()` row still passes. None of their SVGs holds a control character, and `encodeURIComponent` turns the space into `%20`, which is in range.
   - Updated to match: the `ICON_HREF_CHARS` docstring (new range, plus a fifth-pass note), the `stripProceduralIcon` docstring ("decodes to printable ASCII") and the error message ("non-printable-ASCII % escape"). The message still contains `outside ICON_HREF_CHARS`.

**New rows, and the guard each one proves.** Each guard was turned off on a scratch copy of the file, the tests were run, and the file was restored by copying the scratch copy back, then checked with `cmp`.

- **Paint-check rows (`the paint check, and the href layer before it, reject a %s`).** Five rows: `fill='\nred'`, `fill='\r#00ff00'`, `fill='r\ned'`, `stroke='\nyellow'` (on a `fill='none'` circle), and the double-quoted `fill="\ncurrentColor"`.
  - Each row calls `validateIconSvg` directly and expects `paint fill=` (or `paint stroke=`).
  - It then builds the same SVG through `iconLink()`, checks that the link contains `%0A` or `%0D`, and expects `outside ICON_HREF_CHARS`.
  - **Old paint regex restored:** all 5 fail on the direct call.
    - Four of them were not rejected at all.
    - `fill='\r#00ff00'` was still rejected, but by the `#hex` check (`color #00ff00`). So that row proves the paint check now reads the value, not that the old gate accepted that exact payload.
  - **Old `%00-%7F` range restored:** all 5 fail on the `iconLink()` assertion. They throw the paint message instead of the href message.
- **Href rows (`rejects an icon href carrying %s with the ICON_HREF_CHARS message`, fifth-pass table).** Built by hand from `encodeURIComponent(GOOD_SVG)`, with `%23f72585` replaced by `%0A%23f72585`, `%23f72585%0D`, `%09%23f72585`, `%0Ared` and `%7F%23f72585`. Each row checks the decoded text, then expects `outside ICON_HREF_CHARS`.
  - **Old range restored:** all 5 fail.
    - The LF, CR and tab rows decode to a palette hex with padding around it, which `validateIconSvg` now accepts, so nothing throws.
    - The `%0Ared` and `%7F` rows throw the paint message instead.
  - This set proves only the href guard.
- **Positive row (`the paint check still strips the ASCII whitespace CSS strips`).** The existing row with spaces around a palette hex still passes through both layers (spaces encode as `%20`).
  - New: `\n#f72585\n`, `\r\n#f72585\t` and `\f#f72585\r` pass a direct `validateIconSvg` call. This exercises the LF/CR/tab/FF part of the trim.
  - New: the same values built through `iconLink()` (giving `%0A`, `%0D`, `%09`, `%0C`) must throw `outside ICON_HREF_CHARS`. That assertion fails when the old range is restored.
  - The direct `not.toThrow` part also passed under the old regex, because the old regex never matched these values at all. It is a regression guard for the trim, not proof that the fix works.
- **Summary of the guard runs:** with the old paint regex, 5 of 79 tests fail. With the old href range, 11 of 79 fail (5 href rows, 5 paint-check rows, 1 positive row).
