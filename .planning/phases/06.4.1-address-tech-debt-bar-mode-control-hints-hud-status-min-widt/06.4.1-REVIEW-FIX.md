Both findings are closed by one commit, 134adf5. It replaces the noscript/template denylist with a structural element allowlist, `INDEX_ELEMENTS`. This is the same move from denylist to allowlist that ended the favicon-SVG findings. The last four review passes each found another element whose contents jsdom and Chrome parse differently: noscript, template, select, and SVG foreign content. The allowlist rejects that whole class, so the gate no longer needs a regex view to model any of them.

The design still uses jsdom and its parser. No regex reads markup.

## Fixed Issues

### WR-01: An SVG-namespace icon link takes its whole subtree out of both views, and the span check passes it

**Files modified:** `src/render/asset-free.test.ts`, `src/types/jsdom.d.ts`
**Commit:** 134adf5 (shared with WR-02)
**Applied fix:**
- **Allowlist.** `checkIndexElements(doc)` runs first in `stripIconLink`. Every element in `doc.querySelectorAll("*")` must be in the XHTML namespace and have a localName in `INDEX_ELEMENTS`. The list is exactly what the real page uses, re-verified with jsdom: html, head, meta, title, link, style, body, main, canvas, div, p, kbd, dl, dt, dd, span, script. The error names the first element that fails, for example `index.html element <svg> (namespace http://www.w3.org/2000/svg) is not in INDEX_ELEMENTS`. querySelectorAll does not enter template contents. That is sound, because template itself is rejected.
- **Link placement guard.** This is kept as defence in depth, because the icon link is the one element the gate removes from both views.
  - The "exactly one icon link" count still covers every link in the document, in any namespace.
  - The link it finds must have `namespaceURI === XHTML_NS` and `parentElement === doc.head`. Otherwise the gate throws `icon link must be an HTML <link> in head`.
  - The raw view now cuts only `nodeLocation(link).startTag`. That span must equal the element's span (same start and end offsets), so the element is exactly its start tag. Otherwise the gate throws `icon link source span is not its <link> tag`. The `<link` / `>` sanity check is kept, now applied to the start tag's span.
- **`src/types/jsdom.d.ts`.**
  - New `SourceSpan` interface with `startOffset` and `endOffset`.
  - `NodeLocation` now extends `SourceSpan` and adds `startTag?: SourceSpan`, which is parse5 8's optional `ElementLocation.startTag`.
  - Checked against jsdom 31.0.1 and parse5 8.1.1. `nodeLocation` returns `impl.sourceCodeLocation`. For the real `<link>`, startTag is 180..539, the same as the element span. For an SVG link, the element span 26..95 runs past its start tag, which ends at 73.
- **New row:** "the gate rejects the WR-01 PoC: an icon link inside an SVG block". This is the reviewer's PoC, built from the real index.html. The real link is removed, and its href is reused inside `<svg><link ...><script>...</script><g/></svg>` placed before `<main id="sandbox">`. The row asserts:
  - jsdom finds exactly one link.
  - That link is in the SVG namespace and holds two children.
  - The gate rejects it with `index.html element <svg>`.

### WR-02: The raw view does not close the `<select>` divergence; a character-reference spelling inside a select passes both views

**Files modified:** `src/render/asset-free.test.ts`
**Commit:** 134adf5 (shared with WR-01)
**Applied fix:**

  - jsdom's select holds no element children.
  - Whether the raw-text regexes see the PoC: true for the first row, false for the char-ref row.
  - The gate rejects it with `index.html element <select>`.
- The rows:

- The doc comments are updated in three places: the module header, which now describes the HTML bullet and the raw view as defence in depth only, the `INDEX_ELEMENTS` docstring, which lists the divergence history, and the `stripIconLink` docstring.
- The raw view and the serialized view both stay. They still guard the attributes and text of allowed elements.
- **Related rows updated.**
  - The noscript row and the two template rows now expect the allowlist message (`index.html element <noscript>` / `<template>`). Their comments name INDEX_ELEMENTS instead of "the template ban".
- **New class rows**, "a `<X>` element is rejected by INDEX_ELEMENTS". Each inserts the fragment before `<main id="sandbox">` and expects `index.html element <X>`:
