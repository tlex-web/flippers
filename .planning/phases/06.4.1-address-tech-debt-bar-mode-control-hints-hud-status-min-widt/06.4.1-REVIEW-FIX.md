### WR-01: A shape with no `fill` renders in SVG's default black, which is off-palette, and the validator (and its own positive row) admits it

**Files modified:** `src/render/asset-free.test.ts`
**Commit:** 09fb06f
**Applied fix:** Every painted shape must now carry its own `fill` attribute.
- **The rule.** Every `rect`, `circle`, `ellipse` and `path` (`ICON_SHAPES`) must declare `fill` on its own open tag. A fill inherited from a parent `<g>` does not count. This is stricter than SVG's own rule, but it can be checked without a parser. The real favicon in `index.html:7-11` already meets it: the rect has `fill='%230b0420'`, the ring circle `fill='none'` and the disc `fill='%23f72585'`.
- **How the check reads the tag (stricter than the review's suggestion).** The review's `/\sfill\s*=/` over `[^>]*` also matches `fill=` written inside another attribute's value. For example, `<path d="M0 0h32v32H0z fill='none'"/>` passes that check and every earlier check, yet it paints a black square, because browsers render path data up to the first error. So the new loop reads each shape's open tag with a quote-aware sticky regex (`ICON_OPEN_TAG`), which consumes each quoted value whole. It then takes the attribute names with `ICON_TAG_ATTR`. A shape tag that does not parse fails with `open tag is malformed` instead of being skipped.
- **Where it runs.** The loop runs after the element and attribute allowlists, so unknown tags and attributes still get their own messages.
- **The suite's own row.** In "admits every allowlisted element with palette paint", the path is now `<path d='M0 0h1v1z' fill='none' stroke='#f72585'/>`.
- **New negative rows (4):**
  - a fill-less `<rect width='32' height='32'/>`, expecting `<rect> has no fill`
  - a fill-less `<path d='M0 0h32v32H0z'/>`, expecting `<path> has no fill`
  - `fill=` inside a `d` value, expecting `<path> has no fill`
  - a shape with an unquoted value (`width=32`), expecting `<rect> open tag is malformed`
- **Docstrings.** The gate docstring (lines 15-21) and the `validateIconSvg` docstring now state the fill rule.
- **Guard-disabled check.** I turned the new loop into a no-op and ran the suite. All four new rows failed with `expected [Function] to throw an error` (53 of 57 passed). So each payload gets through every other check in `stripProceduralIcon`, and only the new fill guard catches it.
- **Requires human verification:** this adds validator logic (a quote-aware open-tag reader), not just syntax. Please confirm that the stricter "own fill on every shape, no inheritance from `<g>`" rule is the policy you want.

### IN-01: A malformed `%` escape in the href fails with a bare `URIError` instead of a named gate fault

**Files modified:** `src/render/asset-free.test.ts`
**Commit:** 735a50b
**Applied fix:**
- **The pattern.** `ICON_HREF_CHARS` is now `/^(?:[A-Za-z0-9\-_.!~*'() =/:]|%[0-9A-Fa-f]{2})*$/`, as the review suggested. A `%` is allowed only before two hex digits.
- **Docstring and message.** The pattern's docstring now says this. The gate's error message names bad `%` escapes ("a raw character or bad % escape outside ICON_HREF_CHARS"). The existing rows, which assert `outside ICON_HREF_CHARS`, still match it.
- **Existing inputs still pass.** The real favicon href only uses valid escapes (`%3C`, `%3E`, `%23`). It passes, as does every existing `iconLink()` row.
- **New rows (3), built by hand.** `iconLink()` never writes a bad escape, so each row builds its href itself:
  - a `%zz` before the closing `</svg>`
  - a trailing `%4` (one hex digit)
  - a trailing lone `%`

  Each row asserts that `decodeURIComponent(raw)` throws `URIError`, that `PROCEDURAL_ICON` matches the link once, and that `stripProceduralIcon` throws the `outside ICON_HREF_CHARS` message.
- **Old-pattern check.** I put back the old `/^[A-Za-z0-9%\-_.!~*'() =/:]*$/` and ran the suite. All three new rows failed with `expected [Function] to throw error including 'outside ICON_HREF_CHARS' but got 'URI malformed'` (57 of 60 passed). That is the bare URIError the finding describes. Then I restored the new pattern.
