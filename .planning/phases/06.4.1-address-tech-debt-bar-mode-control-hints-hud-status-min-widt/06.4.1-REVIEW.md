## Summary

This re-review covers `git diff 63d6cf5 HEAD -- src/render/asset-free.test.ts`, which holds commits 7ccaad6 (WR-01: reject `&`) and bdd0a4c (WR-02: `ICON_ELEMENTS` allowlist). I read the whole file. `npx vitest run src/render/asset-free.test.ts` passes 46 of 46 tests.

The two fixes close what they target:
- **Character references:** a literal `&` is rejected at both the HTML attribute layer and the XML layer.
- **Elements:** element names are now allowlisted, and comments, CDATA, PIs and uppercase tags are all rejected.
- **New cases:** the negative rows exercise each guard. The fixer reports that each row fails with its guard disabled.

The validator still checks different text from what the browser renders, through a decoding layer the fix did not cover: the WHATWG URL parser deletes every raw tab, LF and CR from a URL before the `data:` body is read.

Attributes are also still a denylist:
- A `style` attribute split by a raw newline passes the validator and paints the icon red.
- A `filter` presentation attribute with CSS filter functions recolors it with no flagged token at all.

I confirmed both with a scratch copy of the validator, where `strip()` returned PASS. Node's `new URL()` turns the payload into `<rect ... style='fill:red'/>`.

As in the previous pass, an SVG loaded as an image is sandboxed (no script, no external fetch), so these are RND-01 gate-soundness defects, not runtime vulnerabilities.

IN-01 and IN-02 from the previous review fell outside fix_scope and are still present, so they are carried forward.

Necessity rubric read (`necessity-review.md`). There are no necessity findings: the `stop-color` paint check is defense in depth behind the element allowlist, not an impossible-state guard.

## Warnings

### WR-01: Raw tab/LF/CR in the href is removed by the browser's URL parser but not by the validator, so split tokens get through the gate

**File:** `src/render/asset-free.test.ts:250-251, 264-278` (`PROCEDURAL_ICON` capture `[^"]*`; `stripProceduralIcon`)
**Issue:**

*Cause.* The capture `[^"]*` admits raw whitespace. `stripProceduralIcon` rejects `&` and then calls `decodeURIComponent`, but it never removes the ASCII tab and newline characters that the URL parser deletes ("remove all ASCII tab or newline from input") before the `data:` body is percent-decoded. This is the same validator-versus-browser gap as the previous WR-01, one layer further on.

*Effect.* Any check that matches a whole token can be split:
- `st⏎yle=` gets past `/\sstyle\s*=/`.
- `on⇥load=` gets past `/\son[a-z]+\s*=/`.
- `u⏎rl(` gets past `/url\(/`.
- `ht⏎tp` gets past the http check.

The element allowlist is not affected, because whitespace ends the captured name.

*Reproduction.* In a scratch copy, `strip()` returned PASS for each of these links:

```
href="data:image/svg+xml,%3Csvg xmlns='http://www.w3.org/2000/svg' ...%3E...%3Crect width='32' height='32' st
yle='fill:red'/%3E%3C/svg%3E"
```

`new URL(href)` gives `...<rect width='32' height='32' style='fill:red'/></svg>`, which is an off-palette paint with no `fill=` attribute and no `#hex` for the later checks to see.

*Why nothing else catches it.* The link is stripped before the PATTERNS scan. Prettier already splits this `<link>` over several lines, so a newline creeping into the long href during a reformat or a hand edit is plausible.

**Fix:** Reject raw URL-parser-stripped characters at the HTML layer, next to the `&` check. Add a hand-built row for each, in the style of the WR-01 `it.each`, so `iconLink()` does not percent-encode them:
```ts
const raw = m[1] ?? "";
if (raw.includes("&")) {
  throw new Error("icon href must not contain HTML character references");
}
if (/[\t\n\r]/.test(raw)) {
  throw new Error("icon href must not contain raw tab or newline (the URL parser strips them)");
}
```
A sturdier option is a positive allowlist of raw href characters that covers what the real favicon uses (for example `/^[A-Za-z0-9%'=\/ .:,()-]*$/`). That also closes any URL-parser normalization nobody has thought of yet.

### WR-02: Attributes are still a denylist, so a `filter` presentation attribute recolors the icon off-palette with no flagged token

**File:** `src/render/asset-free.test.ts:165-177, 209-241`
**Issue:**

*Cause.* WR-02 moved elements to an allowlist, but attributes are still covered only by `ICON_FORBIDDEN` and by the `fill`/`stroke`/`stop-color` paint regex.

*Effect.* An unlisted color-changing attribute gets through. With no splitting or encoding at all, `strip()` returned PASS for this rect (scratch copy):

```
<rect width='32' height='32' rx='7' fill='#0b0420' filter='invert(1) drop-shadow(0 0 2px red)'/>
```

`filter` is a presentation attribute whose grammar includes the CSS filter functions. In browsers that apply them to SVG content, `invert`, `hue-rotate`, `sepia` and `drop-shadow(... red)` repaint the icon off-palette. The paint regex never sees a `filter=` value, and the `#hex` scan never sees a named color.

The docstring at lines 196-202 still says the function "Throws unless `svg` is a static, palette-colored drawing". This is the same "anything unlisted is allowed" weakness the previous WR-02 described, moved from elements to attributes.

**Fix:** Allowlist attribute names as well, and run the check alongside the element check:
```ts
const ICON_ATTRS: ReadonlySet<string> = new Set([
  "xmlns", "viewBox", "width", "height", "x", "y", "rx", "ry",
  "cx", "cy", "r", "d", "fill", "stroke", "stroke-width", "transform",
]);
for (const m of svg.matchAll(/\s([^\s=/>]+)\s*=/g)) {
  const name = m[1] ?? "";
  if (!ICON_ATTRS.has(name)) throw new Error(`icon SVG attribute ${name} is not allowed`);
}
```
This would also close WR-01's split cases at the XML layer: `st⏎yle=` leaves the attribute name `yle`, which is not allowed. The WR-01 raw-href fix should still go in, because it is the root cause. Add negative rows for `filter='invert(1)'` and `opacity='0.3'`.

## Info

### IN-01: "no rgba value" assertion is tautological (carried from the previous review)

**File:** `src/render/asset-free.test.ts:389`
**Issue:** `PALETTE_HEX` is built (lines 147-151) by filtering on `/^#[0-9a-f]{6}$/i` and lowercasing, so `[...PALETTE_HEX].every((v) => /^#[0-9a-f]{6}$/.test(v))` can never fail.
**Fix:** Assert that a known rgba export is absent, for example `expect(PALETTE_HEX.has(palette.WALL_GLOW.toLowerCase())).toBe(false)`. Otherwise drop the line.

### IN-02: Three tests run the same real-index.html validation (carried from the previous review)

**File:** `src/render/asset-free.test.ts:316-319, 375-378, 409-411`
**Issue:** The main scan test, "carries exactly one procedural SVG icon link…" and "the real index.html still passes the payload validation" all call `stripProceduralIcon(indexHtml)`. The third adds no coverage, and one fault fails all three tests.
**Fix:** Remove the "still passes the payload validation" test, or fold it into the "exactly one" test.

### IN-03: Opacity attributes blend palette colors into off-palette rendered colors

**File:** `src/render/asset-free.test.ts:222-227`
**Issue:** `opacity`, `fill-opacity` and `stroke-opacity` pass the validator (a scratch copy returned PASS for `opacity='0.3'`). Alpha compositing of palette colors produces rendered colors that are not in palette.ts. Whether that breaks the "palette only" promise is a judgment call. The current favicon uses no opacity.
**Fix:** Leave the opacity attributes out of the WR-02 attribute allowlist, unless partial opacity is meant to be allowed. If it is, say so in the docstring.
