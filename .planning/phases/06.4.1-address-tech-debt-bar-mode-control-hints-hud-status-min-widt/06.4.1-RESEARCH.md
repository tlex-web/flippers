## Summary

The three fixes are CSS and markup edits to `index.html`, each pinned by a raw-string test. None of them needs JavaScript.

1. **Bar-mode hint.** Add a static `<p class="hud-hint">` right after `#hud-status`. In bar mode it shares the `status` grid cell. It is shown only while `.hud-status` is `:empty`, and it is hidden with `visibility: hidden` (not `display: none`), so it always contributes to the row height. The bar height stays the same in every state, which keeps 06.4 truth 4.
   - It shows after Enter (the serve), which is when Space and the flippers matter.
   - Any status message (attract prompt, TILT, BONUS, GAME OVER) hides it.
   - In side mode it is `display: none`, so the side panel's width and the measured switch are untouched.
2. **WR-02.** Reserve the widest status in CSS: `.hud-status { min-width: calc(23 * (1ch + 0.12em)); }` on the base (side) rule, reset in bar mode. The panel is then as wide at boot as it will ever be, so the single boot measurement in `applyView` holds in every state. A test computes the 23 from `statusText` over every `StatusCode`.
3. **Favicon.** Add `<link rel="icon" type="image/svg+xml" href="data:image/svg+xml,...">` with solid palette fills and no gradients. A live Vite 8.1.4 build keeps it inline and emits no asset.

**Critical pitfall: the favicon fails the existing RND-01 gate.** `src/render/asset-free.test.ts` has an `icon link` pattern and a `data: URI asset` pattern. Both match the favicon, and a live scan confirmed it. The plan must amend the gate with a narrow, validated carve-out for exactly one procedural SVG icon. It must not delete either pattern.

**Primary recommendation:** One plan of three CSS/markup tasks plus their tests (hint, min-width, favicon with the gate carve-out), then a gate-and-UAT plan. Fold in IN-03 (nearly free, same selector). Defer IN-01.

## Architecture Patterns

### Data flow (unchanged except the CSS)

```

                                                                │
                              CSS: .hud-status:not(:empty) + .hud-hint {visibility:hidden}

boot / resize / dpr ──> applyView ──measure #hud.right (side form, status min-width reserved)──>
      sideHudClears ? side : (data-hud="bar" → measure bar height → heightUnderBar → fit)
```

### Pattern 1: Hint shares the status cell and is shown only while the status is empty (Fix 1)

**What:** Static hint markup placed directly after `#hud-status`. In bar mode both elements get `grid-area: status`, so they overlap in one cell. The hint is made `visibility: hidden` whenever the status has text.

**Why this over the alternatives:**
- A fourth always-on row would add about 23 px to the bar and shrink the table at height-limited viewports (768x1024, 320x568).
- A HudView sink for a "ready" state would need a new signal. GameState has no ready state, and the ball resting on the plunger is plain `"playing"` [VERIFIED: hud.ts:113-121, `case "playing": case "tilted": case "bonus":`]. It would also need mode awareness (side vs bar) that HudView does not have.
- Writing the hint into `#hud-status` itself would make it an `aria-live` announcement and the widest status string (about 31 chars). That would widen the side panel, which is the opposite of the WR-02 fix.

**Height invariance:**
- `visibility: hidden` keeps the hint in layout, so the row height is max(status, hint) in every state.
- Make the hint's line box equal the status's: 12 px × `line-height: 1.6` = 19.2 px, the same as the status's 16 px × 1.2 = 19.2 px. The bar then stays 102 px.
- Keep `<kbd>` inline (a block `<p>`, not flex) so its 1 px borders do not grow the line box. Inline borders do not affect line height [ASSUMED, standard CSS 2.1 inline formatting]. A flex `<p>` would blockify the kbds and add about 2 px. That is still constant across states, but it is a new bar height.

**When it shows:**

| Moment | Shown? |
|--------|--------|
| Attract ("PRESS ENTER TO START") | hidden |
| After Enter (ball on the plunger, status `none`) | shown |
| During play with an empty status | shown |
| TILT / WARNING / BALL SAVED / SKILL SHOT / BONUS / GAME OVER / NEW HIGH SCORE | hidden |

This is a slight superset of the audit's "attract/ready". Showing it in attract is impossible without displacing the Enter prompt. Leaving it visible during play is a muted, 12 px, static line. See Assumption A1 (user confirmation at UAT).

```html
<!-- index.html, directly after #hud-status (no whitespace inside #hud-status: :empty must match) -->
<div id="hud-status" class="hud-status" role="status" aria-live="polite"></div>
<p class="hud-hint">Hold <kbd>Space</kbd> to launch · <kbd>←</kbd> <kbd>→</kbd> flip</p>
```
```css
/* Bar-mode control hint (06.4.1, 06.4-UI-REVIEW fix 1): static, not announced.
   Side mode shows the full controls list instead. */
.hud-hint {
  display: none;
}
#sandbox[data-hud="bar"] .hud-hint {
  display: block;
  grid-area: status; /* shares the status cell */
  min-width: 0; /* never widens the grid (320 px) */
  margin: 0;
  overflow: hidden;
  white-space: nowrap;
  text-overflow: ellipsis;
  font-size: 12px;
  line-height: 1.6; /* 19.2 px = the status row's 16 px x 1.2: the bar keeps its height */
  color: var(--text-muted);
}
/* Any status text hides it; visibility (not display) keeps the row height constant. */
#sandbox[data-hud="bar"] .hud-status:not(:empty) + .hud-hint {
  visibility: hidden;
}
/* extend the existing kbd rule: */
.hud-controls kbd,
.hud-controls-note kbd,
.hud-hint kbd { ... }
```

**Width at 320 px:**
- "Hold Space to launch · ← → flip" has 31 visible code points plus 3 kbd caps (each 8 px padding + 2 px border).
- Menlo 12 px: about 31 × 7.2 + 30 ≈ 254 px. Consolas: about 235 px. Both fit the 278 px content box at 320 px [ASSUMED glyph widths].
- `overflow: hidden; text-overflow: ellipsis` covers viewports below about 300 px.

**Accessibility:**
- The hint is not a live region, so it is never announced repeatedly.
- In bar mode the `<dl>` rows are `display: none` and therefore out of the accessibility tree, so the visible hint is the only control info AT sees there.
- In side mode the hint is `display: none` and the `<dl>` is present, so nothing is duplicated.
- When the hint is hidden by `visibility`, it is also out of the AT tree.

### Pattern 2: Reserve the widest status in CSS (Fix 2, WR-02)

```css
.hud-status {
  min-height: 1.2em;
  /* WR-02: reserve the longest status ("GAME OVER · PRESS ENTER", 23 code points,
     hud.ts statusText) so the side panel is already full width when applyView
     measures it at boot with an empty status. Monospace: each glyph is 1ch,
     plus letter-spacing after each one. Pinned by hud-layout.test.ts. */
  min-width: calc(23 * (1ch + 0.12em));
  white-space: nowrap;
  ...
}
#sandbox[data-hud="bar"] .hud-status {
  grid-area: status;
  line-height: 1.2;
  min-width: auto; /* the bar row spans the full width; keep the 06.4 behavior */
}
```

- `ch` resolves against the element's own font, which is bold 16 px monospace. Every glyph used (A-Z, space, digits, comma, U+00B7) is in the fallback chain's fonts.
- In monospace fonts the `·` advance equals `ch` [ASSUMED: all monospace fonts in the chain are fixed-pitch for Latin-1].
- N × (1ch + 0.12em) is an upper bound whether or not the UA adds trailing letter-spacing.
- Side effect: at boot the side panel's right edge moves from 284 to about 296 (Consolas) or about 316 (Menlo). The side/bar threshold at vh 900 rises from vw ≈ 1084 to about 1109 or 1148, so viewports in that band now get the bar. That is the correct result, because those viewports did overlap on GAME OVER.

**Rejected alternatives:**
- (b) Have `applyView` write the widest status, measure, then restore. That adds DOM writes in the resize path, races HudView's write-on-change cache (`lastCode` at hud.ts:217), and needs a browser to test.
- (c) A fixed px panel width. The `<dl>` width depends on font metrics and on the layout-map key labels.

### Pattern 3: Inline SVG favicon from the palette (Fix 3)

```html
<link
  rel="icon"
  type="image/svg+xml"
  href="data:image/svg+xml,%3Csvg xmlns='http://www.w3.org/2000/svg' viewBox='0 0 32 32'%3E%3Crect width='32' height='32' rx='7' fill='%230b0420'/%3E%3Ccircle cx='16' cy='16' r='11' fill='none' stroke='%234cc9f0' stroke-width='2.5'/%3E%3Ccircle cx='16' cy='16' r='6' fill='%23f72585'/%3E%3C/svg%3E"
```

- **Motif:** a bumper (a magenta `BUMPER_CAP` cap inside a cyan `WALL` ring on the `BG_BOTTOM` space color). It matches the HUD's cyan/magenta pair. Palette values [VERIFIED: src/render/palette.ts:12, 24, 34]: `BG_BOTTOM = "#0b0420"`, `WALL = "#4cc9f0"`, `BUMPER_CAP = "#f72585"`. The motif itself is discretion and can be swapped at UAT.
- **Encoding rules:**
  - Write `#` as `%23` (a raw `#` starts the URL fragment and truncates the SVG).
  - Write `<` and `>` as `%3C` and `%3E`.
  - Use single quotes inside the SVG.
  - Keep `xmlns` (required for SVG as an image).
  - Use no gradients or `url(#id)`, which would also trip the gate's `url()` pattern. Use no `<image>`, `<use href>` or `<style>`.
- **Build behavior** [VERIFIED: live probe, vite v8.1.4]: a scratch project with this exact `<link>` built to `out/index.html` with the `href` byte-identical and inline, and `out/assets/` held only the JS chunk. No icon file was emitted.
- **Gate scan of that markup** [VERIFIED: live probe running the asset-free patterns from asset-free.test.ts:35-118]: `url() false`, `ext false`, `icon link true`, `remote false`, `data uri true`.
- **Browser support** [CITED: caniuse.com/link-icon-svg]: Chrome 80+, Edge 80+, Firefox 41+, Safari 26.0+ (desktop and iOS); Safari 18.7 and earlier do not support it. The 404 was observed in Chromium (the Playwright MCP pass). Older Safari falls back to its default icon, which is accepted because an `.ico` would be a file asset.
- **CSP:** none exists. `index.html` has no `Content-Security-Policy` meta, and no SECURITY.md in `.planning` mentions one [VERIFIED: grep of index.html and `.planning/**/*.md` for `Content-Security`, 0 hits]. If a CSP is added later, it needs `img-src data:` for the icon.

### Anti-Patterns to Avoid
- **`display: none` to hide the hint.** The row height would then depend on state if the hint is ever taller than the empty status. Use `visibility: hidden`.
- **Whitespace inside `#hud-status` markup.** `:empty` would stop matching, and the hint would never show. Keep `...aria-live="polite"></div>` closed with no content.
- **Writing the hint through `#hud-status`.** It would be announced (`aria-live`) and would widen the side panel.
- **Deleting the `icon link` or `data: URI asset` gate patterns.** Carve out exactly one validated SVG icon. Any other icon link or `data:image/png` must still fail.
- **A JS-inserted favicon (canvas `toDataURL` plus `createElement("link")`).** It dodges the gate textually instead of amending it, and it adds boot JS.
- **Re-measuring the HUD in the frame loop or on HUD writes.** That violates RND-02.

## Don't Hand-Roll

| Problem | Don't Build | Use Instead | Why |
|---------|-------------|-------------|-----|
| Show hint only when no status | JS state flag / MutationObserver / new HudView sink | CSS `.hud-status:not(:empty) + .hud-hint` | HudView already writes `""`. Zero runtime cost, and testable as a raw string. |
| Panel width invariance | Re-measure in applyView with temp text | CSS `min-width` in `ch`/`em` | Declarative, font-scaled, and pinned to `statusText` by a test. |
| Favicon | Canvas-rendered icon at boot | Static inline SVG data URI | No JS, no flash, and Vite keeps it inline. |

## Common Pitfalls

### Pitfall 1: The favicon fails the RND-01 asset gate (certain)
**What goes wrong:** `npx vitest run` goes red: `/index.html: icon link` and `/index.html: data: URI asset`.
**Why:** `asset-free.test.ts` bans both on purpose. 05-REVIEW IN-04 (commit 309a1b0) added `icon link`, with the sample `'<link rel="icon" href="favicon.ico">'`. IN-03 added `data: URI asset`, with the regex `/["'`]data:(image|audio|font|video)\//i`.
**How to avoid:** In `asset-free.test.ts`, before scanning `index.html`, validate and strip exactly one procedural icon link.
- The link must match `/<link\s+rel="icon"\s+type="image\/svg\+xml"\s+href="data:image\/svg\+xml,([^"]*)"\s*\/?>/`. Allow whitespace between attributes, because Prettier puts each attribute on its own line.
- After `decodeURIComponent`, the payload must start with `<svg xmlns='http://www.w3.org/2000/svg'`.
- It must contain none of: `url(`, `href`, `<image`, `<use`, `<script`, `<style`, `<foreignObject`, `@import`, or `http` outside that `xmlns`.
- Every `#rrggbb` in it must equal an export of `src/render/palette.ts` (a "styled from the palette" pin).
- Then scan the stripped HTML with the unchanged patterns. Add negative tests: a second icon link still fails, and a `data:image/png` still fails.
- Update the gate's header comment to name the one allowed icon.

**Warning signs:** The gate is edited by deleting a pattern, or the carve-out matches more than one link.

### Pitfall 2: The hint widens the grid at 320 px
**What goes wrong:** A nowrap grid item spanning both tracks contributes its min-content width. The bar overflows and the page gains horizontal scroll.
**How to avoid:** Give the hint `min-width: 0; overflow: hidden; text-overflow: ellipsis`. Keep the copy at 31 visible code points or fewer, and pin that in a test.

### Pitfall 3: The status `min-width` leaks into bar mode
**What goes wrong:** At about 266 px (Menlo), a bar narrower than about 300 px overflows.
**How to avoid:** Set `min-width: auto` in `#sandbox[data-hud="bar"] .hud-status` and pin it.

### Pitfall 4: IN-03 breaks an unrelated test
**What goes wrong:** Adding `class="..."` to the Mute `<dt>` makes `key-labels.test.ts:264`, `/<dt>/g`, count 5.
**How to avoid:** If IN-03 is taken, change that regex to `/<dt[\s>]/g`. Also update `hud-layout.test.ts:68-76` to pin the new selector, and assert that exactly the Mute `<dt>`/`<dd>` carry the marker.

### Pitfall 5: The hint flashes once at boot
**What goes wrong:** Before the first `HudView.update`, `#hud-status` is empty, so in bar mode the hint can show for at most one frame before "PRESS ENTER TO START" replaces it.
**Note:** Low impact. The side→bar switch at boot has the same one-frame window today. Check it at UAT; do not add JS for it [ASSUMED: paint timing of deferred module scripts].

### Pitfall 6: Prettier reflows the `<link>`
**What goes wrong:** `npx prettier --check .` includes `index.html`, and Prettier puts each attribute on its own line, as in the example above.
**How to avoid:** Run `npx prettier --write index.html` before writing the test regex. Allow `\s+` between attributes.
