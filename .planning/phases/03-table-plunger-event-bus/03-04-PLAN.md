<objective>
Grow the existing zero-alloc pooled `drainEvents()` into a typed, one-way collision
bus (SC#4): evolve `CollisionEvent` with orthogonal spec-sourced identity
(`elementKind`, `elementId`, explicit `ballId`, normalized ball-side/element-side),
add a `begin-contact` handler so SENSOR lanes/rollovers actually emit (Planck
sensors never fire `post-solve` — the one non-obvious trap), add a symmetric
`onPostStep` seam to the loop, and add a thin `CollisionRouter` that drains once per
fixed step and fans the reused view to N listeners in fixed registration order.

Purpose: satisfy SC#4's "typed one-way bus, one source, can't drift" and give
Phase-4 rules / Phase-5 render+audio a multi-consumer stream — while preserving
every hard-won property (zero per-frame allocation, strictly one-way, one
deterministic batch per simulated step). Do NOT explode a per-pair enum; keep the
coarse `type` and switch on orthogonal `elementKind`/`elementId` (D-12).

Output: evolved `CollisionEvent` + normalized/sensor emit paths, `onPostStep`,
`CollisionRouter`, and the RED->GREEN Wave-0 proofs. The demo stub consumer + the
composition wiring are 03-05.
</objective>
