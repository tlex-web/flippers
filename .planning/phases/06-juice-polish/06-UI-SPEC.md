# Phase 6 — UI Design Contract

> The visual and interaction contract for Phase 6: Juice & Polish (PLSH-01..08). Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **Baseline:** the Phase 5 space theme as it exists in code. These are the only token sources: `src/render/palette.ts` for the canvas and the `:root` custom properties plus the `.hud*` rules in `index.html` for the DOM HUD. This contract extends them and redefines nothing. Each value records its source: **[CTX D-nn]** means a locked decision in 06-CONTEXT.md, **[CODE]** means it already exists in the codebase, and **[SPEC]** means this document chose it within the discretion that CONTEXT allows.
>
> **Hard frame rules (D-24, unchanged):**
> - The live `draw()` has no `shadowBlur`, no `ctx.filter`, no closures and no string building, uses index loops only, and allocates nothing.
> - Sprites and gradients are baked at `resize`.
> - The canvas paints no text, so every word in this spec is DOM.
> - No image, font or audio file enters the tree (`asset-free.test.ts`).
> - 60 fps holds, with every frame stepped at 144 Hz.

Exceptions (pre-existing and frozen; this phase does not touch them or copy them into new elements):
- `.hud` `padding: 12px 16px`. 12px is on the 4-pt grid.
- `.hud-controls` `margin: 10px 0 0` and `column-gap: 12px`.

**Canvas (world meters).** Canvas geometry is specified in meters, because the view transform maps meters to device px. At the reference 1280×684 viewport there are about 107 CSS px per meter, so the ball radius of 0.2 m is about 21 CSS px. All canvas sizes are listed in the Canvas Visual Contract below. The shake amplitudes are the only canvas values given in CSS px, and they are multiplied by `dpr`.

## Canvas Visual Contract

**Focal hierarchy:** the ball is the primary anchor and lit lamps come second. The vignette and light pool frame the lower-center play area, which is where the eye should rest. Particles are fleeting and thin: no particle ever out-glows the ball or stays longer than its 0.45 s life. Unlit lenses and walls recede.

### Live frame draw order (replaces the order in `TableRenderer.draw`)

1. At identity, `fillRect` the whole backing with `BG_BOTTOM`. A shaken blit then never uncovers an edge strip **[CTX D-17]**.
2. Blit the static layer at `(shakeX, shakeY)` device px. Both values are **rounded to whole device pixels** so the neon lines stay crisp.
3. Set the world transform `setTransform(s, 0, 0, s, offX + shakeX, offY + shakeY)`. Every later `setTransform` reset in the frame (bats, balls, flipper flash) must add the same `(shakeX, shakeY)` so all layers stay registered.
4. **Lamp pass.** Rollover lenses, skill chevrons, inlane arrows and the ball-save ring, each at its lamp level. This replaces `drawLitRollovers`.
5. **Flash pass** (existing, unchanged).
6. **Ball-save post**, only while it is visible.
7. Bats.
8. Plunger and meter.
9. **Ball shadows**, one per ball, source-over **[CTX D-20]**.
10. Balls.
11. **Particle pass**, under `"lighter"`. It is drawn last, so sparks read over the ball.
12. Reset `globalAlpha = 1` and `globalCompositeOperation = "source-over"` **[CODE]**.

### Screen shake (PLSH-01) — presentation-only, step clock **[CTX D-17]**

| Parameter | Value |
|-----------|-------|
| Nudge kick | A spring-damper at 8 Hz natural frequency with ζ = 0.55. The initial velocity is sized for a 6 CSS px peak. The view moves **opposite** to the ball's nudge impulse (−`NUDGE_DIRS[dir]`), because the cabinet moved and the ball lagged. Triggered by the new `nudge` cue carrying the direction |
| Trauma shake | offset = `8 · dpr · trauma² · n(t)`. Each axis of `n(t)` is the mean of two sines on the step clock: x uses 13.1 Hz and 19.7 Hz, y uses 15.3 Hz and 22.9 Hz, with fixed phases. There is no RNG |
| Trauma inputs | tilt +0.70, drain +0.25, bumper +0.12 · strength, sling +0.08 · strength. The bank bonus adds 0. Trauma is clamped to [0, 1] |
| Trauma decay | Linear, 1.5 per second (that is, 1.5 / 120 per fixed step) |
| Combined clamp | \|shakeX\|, \|shakeY\| ≤ 12 · dpr device px |
| Reduced motion | When `prefers-reduced-motion: reduce` is set, the kick and the trauma output are both exactly 0 **[CTX D-18]** |
| DOM | The HUD and the bonus overlay never shake |

Perceptual target: a nudge reads as a single shove-and-settle of about 0.25 s. A three-bumper chain moves the view about 1 CSS px and never reads as jitter. A tilt is the only shake that is clearly visible.

### Depth (PLSH-03) **[CTX D-20]**

| Element | Contract |
|---------|----------|
| Ball shadow | A radial sprite baked at resize: radius 1.25 · `BALL_RADIUS_M` (0.25 m), going from `SHADOW_CORE` at the center through `rgba(0,0,0,0.25)` at 50% to `SHADOW_FADE` at the edge. It is drawn at ball center + (0.06, 0.09) m, which is (+0.3r, +0.45r) down-right and matches the top-left `BALL_GLINT` light. The sprite is fixed: it does not scale with speed |
| Light pool | Baked first, right after the background: a `"lighter"` radial gradient from `LIGHT_POOL` to `LIGHT_POOL_FADE`, centered at (1.45, 4.6) m with radius 2.6 m. It brightens the lower-center play area |
| Drop shadows | Baked before each element. Bumpers and slings use a `DROP_SHADOW` fill offset by (0.04, 0.06) m with bake-time `shadowBlur` equal to 0.04 m · scale. Walls use a `DROP_SHADOW` stroke 0.04 m wide offset by (0.02, 0.03) m, drawn under the neon. Every shadow falls down-right |
| Vignette | Baked **last**, over the elements: a radial gradient from the backing center, transparent out to 0.5 × the half-diagonal and reaching `VIGNETTE_EDGE` (0.4 black) at the half-diagonal |
| Not used | Point-light shadows and any live vignette overlay **[CTX D-20]** |

### Insert lamps (PLSH-04) **[CTX D-21, D-22]**

**Lens look** (applies to every lamp):
- **Unlit (baked into the static layer):** the lens shape filled with its `*_UNLIT` color, plus a `LAMP_RIM` stroke 0.008 m wide along the upper-left half of the outline.
- **Lit (live):** draw these three layers at the lamp level `L` in [0, 1]:
  1. the lens filled with `*_LIT` at `globalAlpha = L`
  2. the baked halo (`bakeHalo` in the lamp's color) under `"lighter"` at `L`
  3. a `LAMP_HOTSPOT` disc of 0.35 × the lens radius, offset (−0.2, −0.2) × the lens radius, at `0.8 · L`
- **Fade:** in over 4 steps and out over 15 steps, through a per-lamp `Float32Array` level array on the step clock, read at `alpha` (the FlashTracker pattern).

| Lamp | Shape and position (m) | Halo radius | Rule state it shows |
|------|------------------------|-------------|---------------------|
| Rollover ×3 (400/401/402) | The existing 0.4 m sensor segment drawn as a 0.03 m round-capped stroke **[CODE]**. Its hot-spot is a 0.01 m white stroke along the middle 50% of the segment | `SENSOR_HALO_M` 0.18 **[CODE]** | Steady: lit for bank progress (`isLit`) |
| Skill chevron ×3 | An upward chevron 0.20 wide × 0.12 tall with 0.05 arm thickness, centered at (0.95, 1.32), (1.45, 1.32) and (1.95, 1.32), just below lanes 400, 401 and 402 | 0.16 | Skill-shot target (see the state map) |
| Inlane arrow ×2 | An upward arrow: a 0.16 × 0.12 head plus a 0.05 × 0.08 stem, centered at (0.585, 4.72). The right arrow is its `mirrorX` (2.315, 4.72) | 0.14 | Steady: that inlane has scored at least once on this ball. Cleared on serve |
| Ball-save ring | A ring lens concentric with the save-post sensor. Inner radius = post radius + 0.02, ring width 0.035 | 0.22 | Ball save armed (see the state map) |

The ball-save post and its sensor are one spec value: the drawn post radius equals the sensor circle `radius` exactly, with no derived offset **[CTX D-07]**. Recommended values: radius 0.09 m, center (1.45, 5.80) m, on the mirror axis between the bat tips and `DRAIN_Y` 6.05. The planner may move it to satisfy the soak gate, but the drawing must keep reading the same field.

**Lamp state map** (every blink is at most 2 Hz: a 60-step period, 30 steps on and 30 off, at least 3× under the WCAG 2.3.1 limit):

| Lamp | State | Display |
|------|-------|---------|
| Skill chevrons | Armed, lane rotating (ball resting, plunger idle) | Steady chase: the selected chevron is lit and moves to the next lane every 72 steps (0.6 s) in the order 400 → 401 → 402 → 400. The 15-step fade-out leaves a soft tail |
| | Frozen (Space press edge) | The frozen chevron **blinks** at 2 Hz until the shot resolves, because it can be collected now. The other two are unlit |
| | Awarded | The chevron is steady-lit for 60 steps, a `SKILL_LIT` glint plays (see Particles), then it fades out |
| | Missed, tilted or not armed | All chevrons are unlit (they fade out over 15 steps) |
| Ball-save ring | Armed, timer not started (ball in chute) or running with more than 240 steps left | Steady lit |
| | Armed, ≤ 240 steps (2 s) left | **Blinks** at 2 Hz |
| | Spent, timed out, tilted or game over | Unlit |
| Rollovers and inlane arrows | Attract (game over) | A ping-pong chase on the step clock in the order 500 → 400 → 401 → 402 → 501 → 402 → 401 → 400, with an 18-step dwell. Each lamp lights at most once every 1.2 s. The skill chevrons and the save ring are unlit |
| All lamps | Tilted | Lamps follow rule state: the skill and save lamps go out (disarmed), and the rollover and inlane lamps keep their state |

### Ball-save post flourish (PLSH-07) **[CTX D-07, D-10]**

| Phase | Steps | Display |
|-------|-------|---------|
| Rise | 3 (25 ms), starting on the kick step | The post is drawn at 0.7R → R as a `POST_BODY` disc with a `SAVE_LIT` rim stroke 0.02 m wide. Collision always happens at R, so the rise reads as a pop-up, not as a size change |
| Flash | The FLASH_BUMPER timing (hold 2, decay 10) **[CODE]** | A `SAVE_LIT` halo at `HALO_SCALE` × R under `"lighter"`, plus 10 `SAVE_LIT` sparks spread ±80° around the kick normal |
| Hold | 48 (0.4 s) | Full post, steady rim |
| Sink | 24 (0.2 s) | R → 0.7R with alpha 1 → 0, then hidden |
| Backstop save (non-center drain) | — | No post. The save ring fades out. The status line shows "BALL SAVED" and the save sting plays |

### Particles (PLSH-02) **[CTX D-19]**

- **Pool:** one struct-of-arrays `Float32Array` pool of **160** slots that overwrites the oldest. Each slot holds x, y, prevX, prevY, vx, vy, age, life, type and size. Particles tick on the step clock and are drawn at `alpha`.
- **Randomness:** a dedicated `mulberry32` stream. Never `Math.random`.
- **Drawing:** under `"lighter"`, one loop per type, so each fixed color string is assigned once per type per frame.

| Emitter | Particles |
|---------|-----------|
| Bumper hit | **1 shockwave ring**: radius 1.0R → 2.0R over 24 steps, line width 0.02 → 0.006 m, alpha 0.9 → 0. **Sparks**: count = round(12 + 4 · strength), so 12–16 **[CTX D-19]**. They spawn at the contact point on the rim and fly within ±80° of the outward normal at 1.5–3.0 m/s, with life 0.30–0.45 s, drag 4/s and gravity +2 m/s² along +y. Each is a streak with length = speed × 0.025 s (minimum 0.02 m) and width 0.012 m |
| Sling kick | Count = round(6 + 4 · strength), so 6–10, centered on the "about 8" of **[CTX D-19]**. They fly within ±35° of the `deriveKickFace` normal from the contact point at 1.2–2.4 m/s, with life 0.20–0.32 s and the same drag, gravity and streak model |
| Rollover, inlane or skill-shot award | **1 baked star glint**: a 4-point star sprite of 0.24 m across, baked once per color, scaling 0.6 → 1.0 while alpha goes 1 → 0 over 42 steps (0.35 s). **3–4 motes**: discs of radius 0.018 m drifting upward (−y) at 0.15–0.30 m/s, life 0.6–0.8 s |
| Ball save | 10 sparks (see the post flourish) |

- **Alpha law:** every particle uses alpha = `(1 − age/life)²`.
- **Photosensitivity:** no filled bright shape exceeds its element's existing halo footprint (ring ≤ 2.0R < `HALO_SCALE`, glint 0.24 m is smaller than the 0.4 m sensor) **[CODE rule]**. Sparks are thin streaks of 0.012 m or less, and with drag their travel stays ≤ 0.63 m.
- **Reduced motion:** particles, flashes and lamp blinks stay on **[CTX D-18]**.

## HUD and Overlay Contract (DOM)

### HUD panel lines (`#hud`, top-left, existing panel) **[CODE + SPEC]**

| Line | Element | When written | Content |
|------|---------|--------------|---------|
| Score | `#hud-score` (existing) | When the **shown** integer changes | An exponential chase `shown += (target − shown) · (1 − exp(−dt/τ))` with **τ = 0.20 s**, rounded. It snaps when \|target − shown\| ≤ 10. It snaps at once under reduced motion and on a new game, so 0 never counts down **[CTX D-14]**. `getScore()` stays the true value |
| Ball | `#hud-ball` (existing) | On a state or ball change | `BALL n / 3` in `playing`, `tilted` **and the new `bonus` state**, and empty in game over |
| Status | `#hud-status` (existing, `role="status"`, `aria-live="polite"`) | On a resolved-text change | See the status table |
| High score | `#hud-best` (**new**, after `#hud-ball`, same style as `.hud-ball`: 16px/400 `--text-soft`, `margin-top: 4px`, tabular-nums) | On a state or best change | `HIGH SCORE 48,250` in game over (attract and after a game). Empty during play. Empty when best = 0 (the empty state) |

**High score pulse:** a new best at game over sets `data-new="true"` on `#hud-best` through an injected attribute sink, which is node-testable and written on change. CSS then runs a keyframe that pulses the text-shadow from `0 0 0` to `0 0 12px var(--accent-glow)` three times at 1.5 Hz (2 s total) and ends steady. The attribute is cleared on the next game start. The pulse stays under reduced motion because it is a flash, not motion.

### Status line priority (highest wins; texts set in `statusText`)

| Priority | Condition | Text | Duration |
|----------|-----------|------|----------|
| 1 | `tilted` | `TILT` **[CODE]** | While tilted |
| 2 | A tilted ball drained (forfeits the bonus) | `TILT · NO BONUS` | A fixed 120-step hold (1.0 s) before the serve or game over **[CTX D-13]** |
| 3 | The `bonus` state | `BONUS 12,000`, with the total known at the drain | For the whole tally. It is announced once |
| 4 | Game over with a new best | `NEW HIGH SCORE` | 360 steps (3 s), then the priority-6 text |
| 5 | A save fired | `BALL SAVED` | 180 steps (1.5 s) |
| 5 | Skill shot awarded | `SKILL SHOT 5,000`, showing the value just paid (5,000–25,000) | 180 steps (1.5 s). The newer of the two priority-5 events replaces the other |
| 6 | Game over | `PRESS ENTER TO START` / `GAME OVER · PRESS ENTER` **[CODE]** | Steady |
| 7 | Playing with the warning open | `WARNING` **[CODE]** | The existing window |
| 8 | Plain play | empty **[CODE]** | — |

Transient durations are counted on the fixed-step clock, never the wall clock, so they freeze on tab blur. Every status text keeps the existing `--status` magenta style. The longest new text, `SKILL SHOT 25,000` at 17 characters, is shorter than the existing 23-character `GAME OVER · PRESS ENTER`, so the panel never widens.

### End-of-ball bonus overlay (`#hud-bonus`, new) **[CTX D-11, D-12, SPEC layout]**

- **Placement:** `position: fixed; top: 50%; left: 50%; transform: translate(-50%, -50%)`. That is the center of the viewport and therefore of the centered table. The ball has drained and the flippers are off, so it covers nothing in play. `pointer-events: none`.
- **Frame:** the same as `.hud`: `--panel-bg`, a 1px `--frame` border, 8px radius, and the same inset and outer glow **[CODE]**.
- **Box:** padding 16px 24px and `min-width: 240px`.
- **Grid:** two columns (label left, value right-aligned) with `column-gap: 24px` and `row-gap: 4px`.
- **Accessibility:** `aria-hidden="true"`, because the status line announces `BONUS n` once.
- **Visibility:** hidden (`hidden` attribute) outside the `bonus` state.

| Row | Style | Copy |
|-----|-------|------|
| Heading | Label role (11px/400, 0.28em, `--label`), spans both columns, `margin-bottom: 8px` | `BONUS` |
| Item | Body 16px/400 `--text-soft`; tabular-nums value | `ROLLOVERS × 3` · `3,000` |
| Item | the same | `INLANES × 2` · `4,000` |
| Item | the same | `BANKS × 1` · `5,000` |
| Total | `border-top: 1px solid var(--frame)`, `padding-top: 8px`, `margin-top: 8px`. Label at 16px/700 `--text`; value at Display 32px/700 `--text` with `text-shadow: 0 0 10px var(--accent-glow)` | `TOTAL` · `12,000` |

The unit values for ROLLOVERS and INLANES are `tuning.ts` constants chosen by the planner. BANKS is 5,000 each **[CTX D-11]**. The figures above only illustrate the format.

**Tally timing** (rule-level counted steps, deterministic **[CTX D-12]**):
- Only rows with n ≥ 1 are included.
- Every included row is laid out from the first step with `visibility: hidden`, so the panel never resizes.
- Each item row is revealed in order with a 48-step budget (0.4 s). During its budget the value counts linearly from 0 to the row value, as a function of the step count.
- TOTAL is revealed last at full value and held for 120 steps (1.0 s).
- The maximum is 3 × 48 + 120 = 264 steps (2.2 s), within the ~300-step cap.
- **All rows zero:** the heading and `TOTAL` · `0` show for a 60-step hold (0.5 s).
- **Reduced motion:** each row shows its final value as soon as it is revealed. Rule timing is unchanged.
- **Audio:** one `bonusTick` cue per row reveal, none per counted step and none on TOTAL **[CTX D-25]**.
- **Skip:** a flipper press latched on a fixed step ends the tally at once. The overlay hides, the bonus is credited, and the next ball is served or the game ends.
- **Credit:** the bonus is credited when the tally ends. The HUD score then counts up with the τ = 0.20 s chase while the next ball is served.

### Sound stings (new `RECIPES` entries, no files) **[CTX D-25]**

| Cue | Character |
|-----|-----------|
