## Phase Goal

**As a** pinball player, **I want to** control two flippers with the keyboard that snap up instantly, fling the ball realistically, and hold a steady cradle, **so that** the moment-to-moment pinball feel is satisfying and faithful to Space Cadet.

> This plan delivers the "can never be passed through" guarantee behind the story: the fastest flip must never sweep through the ball. It is the mechanism; plan 02-05 is its seeded proof.

<objective>
Insert adaptive angular sub-stepping into `PlanckWorld.step()` (D-01) — the primary, hard rotational anti-tunnel guarantee (FLIP-04). When a flipper's live angular speed is high, split the `FIXED_DT` step into `N` Planck sub-steps so per-sub-step tip travel stays below ~half a `BALL_RADIUS_M`, shrinking the bat's per-sub-step arc below what Planck's discrete narrow phase can miss (Planck/Box2D TOI sweeps translation — the ball's `setBullet` already handles that — but can miss a large/fast rotation; Erin Catto, GDC 2013). Add the secondary angular-speed cap that bounds `N` (D-02), and a `subStepping` off switch so the plan 02-05 negative control can prove the mechanism has teeth.

Purpose: this is the make-or-break FLIP-04 property. It lives entirely behind the unchanged `PhysicsWorld` interface, so the harness and every consumer are untouched; only `step()` changes. The `subStepping` toggle is the D-03 requirement's other half — a green gate is only trustworthy if forcing the mechanism off turns it RED.
Output: an `N`-sub-step `step()` that stays deterministic, accumulates events across sub-steps, syncs pools once at the end, and is bounded against a pathological omega — plus a unit test proving the sub-step count law and the off-switch.
</objective>
