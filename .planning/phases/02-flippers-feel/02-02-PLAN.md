## Phase Goal

**As a** pinball player, **I want to** control two flippers with the keyboard that snap up instantly, fling the ball realistically, and hold a steady cradle, **so that** the moment-to-moment pinball feel is satisfying and faithful to Space Cadet.

> This plan builds the control brain behind the story's "control with the keyboard" and "hold a steady cradle" clauses, proven in isolation against synthetic events and a spy world before it is wired to the real rig in plan 02-03.

<objective>
Build the two engine-agnostic pure-TypeScript pieces of the flipper control layer, each unit-proven in isolation (D-05 makes this possible): (1) `src/input/flipper-input.ts` — the first keyboard handling in the codebase (D-10): a held `Set` of `event.code`s with per-side OR edge detection, auto-repeat suppression, `preventDefault` on bound codes only, and blur/visibility force-clear; and (2) `src/control/flipper-controller.ts` — the explicit `resting -> flipping-up -> held-up -> returning` state machine (D-05) that drives the world's `setFlipperMotor` hook and holds `+1` continuously through the cradle (D-06(1)).

Purpose: this is the make-or-break control path for FLIP-01 (near-instant, no stuck-key/auto-repeat artifacts) and FLIP-03 (explicit cradle state machine). Keeping both engine-agnostic and unit-testable against a fake `PhysicsWorld` / synthetic events is exactly the D-05/D-10 contract; it also means a future custom solver reuses them unchanged.
Output: two new modules with passing unit tests, importing NO physics engine, ready to be wired end-to-end in plan 02-03.
</objective>
