<decisions>
## Implementation Decisions

### Hint trigger
- **D-01:** The bar hint shows only while the ball in play rests on the plunger: state `"playing"` and the ball resting in `PLUNGER_ZONE`. That includes while Space is held (charging). It hides once the ball leaves the zone and comes back after a weak plunge that falls back. This supersedes 06.4.1 A1 = A ("hint whenever no status shows").
- **D-02:** The signal is a new public, read-only `GameSession` getter (name at Claude's discretion, e.g. `isBallOnPlunger()`) that delegates to the existing private `activeRestingInZone()` (`src/game/game-session.ts:678`). It adds no state and changes no step behavior. It is exposed through `HudSource`. The skill-shot phase is NOT the signal: it stays `frozen` during launch travel and is `off` if the ball returns to the plunger after the shot has resolved.
- **D-03:** Visibility is driven by an explicit attribute that `HudView` writes (via the existing `TextSink.setAttribute` pattern, as `data-new` on the best line). It replaces the `.hud-status:not(:empty) + .hud-hint` selector. The status still wins: the hint is visible only when ready AND the status code is `"none"`, so it never overlaps WARNING or any other status. It stays `visibility: hidden`, not `display: none`, so the bar keeps one height (06.4.1 truth 2). This also closes 06.4.1-UI-REVIEW fix #3 (the `:empty` coupling).
- **D-04:** It shows on every serve, balls 1-3. No per-game latch.
- **D-05:** The copy stays "Hold Space to launch · ← → flip". Side mode is unchanged: `.hud-hint` stays `display: none` and the full controls list shows.

### Type size
- **D-06:** All three 11 px sites go to 12 px: `.hud-label` (`index.html:157`), `.hud-controls-note` (`:288`), `.hud-bonus-heading` (`:347`). No `font-size` below 12 px remains in `index.html`, and a test guards that.
- **D-07:** After the change, re-measure the side panel width and the side/bar switch point. The 23ch status reserve test in `src/ui/hud-layout.test.ts` and the constant bar row height must stay green.

### 06.4.1 re-verification
- **D-08:** Re-run gsd-verifier, secure-phase and validate-phase for 06.4.1 at HEAD. The refreshed records must:
  - name the jsdom 31.0.1 devDependency, `src/types/jsdom.d.ts` and the current gate functions (`stripIconLink`, `decodeIconHref`, `checkIconSvg`, `INDEX_ELEMENTS`);
  - replace the stale VERIFICATION truths 9, 10 and 13 and SECURITY T-06.4.1-09, T-06.4.1-SC and AR-06.4.1-01, which say no package changed;
  - record jsdom as an accepted supply-chain item: user-requested in quick 261125-0es, exact pin, dev-only, absent from `dist`.
- **D-09:** The favicon gate's review loop is closed. This phase runs no more review-fix rounds on `src/render/asset-free.test.ts`, and the verifier's read covers 134adf5. This phase's own code review covers only the files it changes.

## Existing Code Insights

### Reusable Assets
- `GameSession.activeRestingInZone()` (`src/game/game-session.ts:678`): private. It applies `isRestingInZone(ball, PLUNGER_ZONE)` to the ball in play and returns false with no ball. The skill-shot rest test at `:594-603` adds a previous-step-idle guard against the release step; the hint does not need that guard.
- `TextSink.setAttribute` (`src/ui/hud.ts:52-58`): HudView already writes `data-new` on the best line (`:284`). Use the same pattern for the hint flag.
- `HudView.update` status resolution (`src/ui/hud.ts:300-340`): `code === "none"` is the "no status" condition the hint gates on.

### Established Patterns
- HudView writes only on change (`lastCode`/`lastValue` diffing). The hint flag should diff the same way, with no per-frame DOM writes.
- Bar-mode CSS (`index.html:59-137`): `#sandbox[data-hud="bar"]` scoping. The hint shares the `status` grid cell, with a 12 px × 1.6 line box equal to the status line's 16 px × 1.2 (pinned by `hud-layout.test.ts:236-239`).
- Raw-string CSS tests in `src/ui/hud-layout.test.ts:155-246` pin the current `:empty + .hud-hint` selector and must be updated to the attribute selector.
- Sim and presentation are separate: presentation reads `GameSession` getters and never writes. Determinism tests (`src/sandbox/*.determinism.test.ts`) must stay bit-identical.

### Integration Points
- `HudSource` interface (`src/ui/hud.ts:63`): add the ready getter. `GameSession` satisfies it structurally.
- `src/sandbox/main.ts`: HudView construction and sinks. The hint `<p>` may need passing in as a sink if the attribute lives on it.
- `index.html:110-127` hint CSS, `:392` hint markup; 11 px at `:157`, `:288`, `:347`.
