## 06.4.1 UI-Review Fixes

1. **Closed.** The hint was stale after launch. It now shows only while `playing && status none && isBallOnPlunger()`.
   It stays visible through the Space charge, drops after launch, and returns on a weak fall-back and on every serve.
   The real-table e2e test traces this (`src/sandbox/skill-shot-e2e.test.ts`).
2. **Closed.** The 11 px labels are raised to 12 px, guarded by the "type scale floor (06.4.1.1 D-06)" tests.
3. **Closed.** The `:empty` sibling rule is deleted. `src/ui/hud-layout.test.ts` asserts it is gone, and the
   write-on-change `data-ready` flag is unit-tested in `src/ui/hud.test.ts`.

## Top Fixes

No BLOCKER. All WARNING.

1. **Measure 320 px truncation.** The hint has `text-overflow: ellipsis` + `nowrap` (:118-122) and may clip to
   "…← →…", losing "flip". Measure at 320 and 345 px. If it clips, shorten the copy (for example "Space launch · ← →
   flip"). The 06.4 IN-01 overflow below about 345 px is also still unmeasured.
2. **Hint legibility.** Muted 12 px beside a 16 px status line; legibility rests on the user's "approved" with no
   numbers. Consider `--text` or a brighter muted tone only if a visual check shows it is weak.
3. **Hint transition.** Visibility flips instantly at launch. Acceptable; a short opacity fade would soften the
   handover. Polish only.

## Minor

- The hint `<p>` carries no aria attributes. `visibility: hidden` removes it from the accessibility tree when not
  ready, which is correct; it is not a live region.
- Side mode unchanged (`.hud-hint { display: none }`).
- No touch input (out of scope).
- Registry audit skipped (shadcn not in use).
