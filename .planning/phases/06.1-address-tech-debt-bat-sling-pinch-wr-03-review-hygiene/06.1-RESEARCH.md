## Summary

**WR-03 is real, worse than the audit says, and fixable with a 3-line spec change.** On TABLE_SPEC at HEAD, a raised bat comes within **0.129 m** of the slingshot's lower edge. The spec's own clearance rule (1) asks for 2·r + 0.05 = 0.45 m. The audit's "~0.29 m" is the gap with the bat level (0.282 m), not raised. I ran a seeded probe: a ball fed down the inlane onto the resting bat, with the flip fired on every fixed step k = 36..110. The worst sustained (3-step) launch was **22.6 m/s on the left bat and 27.9 m/s on the right**, with peaks of 27.0 and 33.2 m/s. That is **2.43× and 2.64×** the identical flip on the same table with the slings removed. 28% of left-bat flip timings and 41% of right-bat timings exceed 1.10× the no-sling control. Perceptually, the pinched ball shoots sideways back toward its own side wall: left (−24.1, −12.1) m/s, right (+19.1, −9.5) m/s.

The audit's "16-19 m/s" came from the Phase-4 reviewer's rig, which I could not reproduce exactly. With the rig as described, I get 9-13 m/s at both HEAD and `f3ab8be`, so that rig under-samples the pinch. The audit's "never playtested" claim is also wrong: 04-UAT test 12 targeted the pinch by feel and passed. A by-feel pass does not cover a timing window that is a few steps wide, and the sweep shows the window is real.

**Recommended fix: translate both slingshots straight up-table by 0.35 m**, and move the inlane sensors with them. The change is `LEFT_SLING` y −0.35, giving vertices (0.86,3.85), (0.86,4.6), (1.16,4.75); `LEFT_INLANE` y → 4.6; mirrors follow automatically. A pure translation keeps the kick-face normal (0.9487, −0.3162) and its length (√0.9 ≈ 0.949 m), so ELEM-02 behavior is unchanged. The bat-to-sling gap becomes 0.458 m over the whole sweep including 2.76° of measured limit overshoot, which meets rule (1). On the same probe, the pinch drops to **0%**: sustained/control ratio 1.00 on both sides, max sustained 11.4/10.6 m/s. I applied this candidate in a scratch worktree. The full suite gave 1282/1288 with 6 known, mechanical failures, and `npm run soak` passed 4/4. Δ = 0.40 was **rejected**: it broke a seeded drain proof (one of 12 save-armed drops never drained), so the geometry response is non-monotonic. Go no further than needed.

### Pattern 2: Seeded probe with a no-sling control and a RED control (project idiom)
The repo already uses RED controls, for example `reactive-table.test.ts:614` "RED control: the same drops with { kickbackSpeed: 20 } break the 15 m/s bound". The pinch test must keep its teeth after the fix, so the RED control rebuilds the **old** geometry locally:

```ts
// Source: probes run this session; APIs verified in src/physics/types.ts:35-44,159-184,
// src/sim/loop.ts:85, src/physics/planck-world.ts:274, src/table/spec.ts:176,366-367.
import { describe, it, expect, vi } from "vitest";
import { BALL_RADIUS_M, FIXED_DT } from "../physics/constants";
import { PlanckWorld } from "../physics/planck-world";
import { FixedStepLoop } from "../sim/loop";
import { PLAYFIELD_CENTER_X, TABLE_SPEC, mirrorPath, type TableSpec } from "../table/spec";

vi.setConfig({ testTimeout: 30_000 }); // heavy-suite idiom (05-REVIEW IN-07)

/** HEAD's pre-fix sling, kept here so the RED control never loses its teeth. */
const OLD_LEFT_SLING = [{ x: 0.86, y: 4.2 }, { x: 0.86, y: 4.95 }, { x: 1.16, y: 5.1 }];
const OLD_SLING_SPEC: TableSpec = TABLE_SPEC.map((e) =>
  e.id === 300 ? { ...e, path: OLD_LEFT_SLING } :
  e.id === 301 ? { ...e, path: mirrorPath(OLD_LEFT_SLING) } : e) as TableSpec;
const NO_SLING_SPEC: TableSpec = TABLE_SPEC.filter((e) => e.id !== 300 && e.id !== 301);

const SUSTAIN_STEPS = 3, WINDOW = 25, K_MIN = 36, K_MAX = 110, PINCH_RATIO = 1.1;

/** Inlane drop, bats drooped, raise bat `id` after k steps; max speed held SUSTAIN_STEPS. */
function inlaneFlip(table: TableSpec, id: 0 | 1, k: number): number {
  const world = new PlanckWorld({ table });
  const loop = new FixedStepLoop(world);
  const step = (d: () => void): void => { loop.advance(FIXED_DT * 1000, d); };
  const droop = (): void => { world.setFlipperMotor(0, -1); world.setFlipperMotor(1, -1); };
  for (let i = 0; i < 30; i++) step(droop);
  const x0 = 0.6; // left inlane; mirrored for the right bat
  world.addBall({ x: id === 0 ? x0 : 2 * PLAYFIELD_CENTER_X - x0, y: 4.5, vx: 0, vy: 1.0, radius: BALL_RADIUS_M });
  for (let i = 0; i < k; i++) step(droop);
  const raise = (): void => { world.setFlipperMotor(id, 1); world.setFlipperMotor(1 - id, -1); };
  const sp: number[] = [];
  for (let i = 0; i < WINDOW; i++) {
    step(raise);
    const b = world.getBalls()[0];
    sp.push(b ? Math.hypot(b.vx, b.vy) : 0);
  }
  let sus = 0;
  for (let i = 0; i + SUSTAIN_STEPS <= sp.length; i++) sus = Math.max(sus, Math.min(...sp.slice(i, i + SUSTAIN_STEPS)));
  return sus;
}

function worstRatio(table: TableSpec, id: 0 | 1): number {
  let worst = 0;
  for (let k = K_MIN; k <= K_MAX; k++) {
    const ctrl = Math.max(inlaneFlip(NO_SLING_SPEC, id, k), 1);
    worst = Math.max(worst, inlaneFlip(table, id, k) / ctrl);
  }
  return worst;
}
```

The per-call `slice` is test-only code; the zero-allocation rule applies to the frame loop. Assert `worstRatio(TABLE_SPEC, id) <= PINCH_RATIO` for both ids, and `worstRatio(OLD_SLING_SPEC, id) > PINCH_RATIO` for both ids as the RED control. Measured: HEAD/OLD 2.43 and 2.64; Δ=0.35 1.00 and 1.00. Cost is about 450 short runs at roughly 9 ms each ≈ 4 s, which puts it in the heavy-suite class. Recommended home: `src/harness/sling-pinch.test.ts` (new file). `PLAYFIELD_CENTER_X` is exported at spec.ts:163 (`export const PLAYFIELD_CENTER_X = 1.45;`) [VERIFIED].

### Pattern 3: Geometric clearance assertion (rule (1) as a test)
Add a case (e) in `src/table/table-world.test.ts` next to "(c) sweeps each bat through its full raise and return with nothing in the way" (:362). Raise each bat with motor +1 for 40 steps and return it, as (c) does, sampling the **simulated** angle every step so the 2.76° overshoot is included. At each sample, compute the capsule axis from `FlipperState`: from pivot + `tipRadius`·d to pivot + (`length` − `tipRadius`)·d, radius `halfWidth`. Take the segment-to-segment distance to every `kind === "slingshot"` element segment and assert min − halfWidth ≥ 2·`BALL_RADIUS_M` + 0.05. HEAD gives 0.129, so this fails RED. Δ=0.35 gives about 0.453 (margin about 3 mm). Reuse the file's `distToSegment` (:273) and `tipOf` (:265).

### Anti-Patterns to Avoid
- **Tuning geometry from a single flip or a coarse sweep.** The response is non-monotonic (t=0.2 worse than t=0.1; Δ=0.40 traps a ball). Sweep every step, both bats, and re-run every seeded drain proof plus the soak.
- **Filtering the sling out of the proof rig.** This is exactly how 04-09 hid the pinch (WR-03's original complaint). The pinch test must run on TABLE_SPEC.
- **Asserting FLIP-02 tip > base on TABLE_SPEC with a free-flight rig.** The sling intercepts the flight. Keep FLIP-02 on OPEN_PROOF_BOX.
- **Editing PROOF_BOX_SPEC or the flipper feel constants.** spec.ts:114 says "Do not edit". Changing the constants changes calibrated FLIP-02/03/04 proofs and the Core-Value feel. The fix lives entirely in TABLE_SPEC.
- **`npm run format` before adding `.prettierignore`.** It rewrites 186 .planning and 43 .gsd files.

## Common Pitfalls

### Pitfall 1: Coarse sampling hides the pinch
**What goes wrong:** The pinch lives in narrow timing windows. Every-3rd-step sampling showed 13.1/17.9 m/s, while every step showed 22.6/27.9.
**How to avoid:** Sweep every fixed step for k in 36..110, on both bats.

### Pitfall 2: Spawn overlap fakes launches
**What goes wrong:** A ball placed overlapping a collider is pushed out by the solver, producing a spurious speed. On HEAD the reviewer-style placement at rFrac ≥ 0.7 overlaps the sling.
**How to avoid:** Use the inlane drop, which starts in open space. Any placement helper should assert clearance at spawn.

### Pitfall 3: Fixing the number and losing the teeth
**What goes wrong:** After the fix, a pinch test on TABLE_SPEC alone would be green whether or not it can detect a pinch. Likewise, `reactive-elements.test.ts:340` would still pass after the move, but for the wrong reason.
**How to avoid:** Keep a RED control pinned to the old geometry. Translate every literal contact point by the same Δ.

### Pitfall 4: Trajectory-dependent e2e tests
**What goes wrong:** Any geometry change reshuffles seeded trajectories. `game-e2e.test.ts:1063` already guards its preconditions explicitly, and it fails loudly (783 vs >1075).
**How to avoid:** Re-run the full suite plus `npm run soak` after the spec edit, before touching any test. Treat each red test as either a literal pin (translate it) or a scenario (re-author it, never loosen it silently).

### Pitfall 5: Ledger id reuse
**What goes wrong:** The disposition gate keys rows by id. A reused id silently replaced 6590dce IN-04.
**How to avoid:** When editing the ledger, cross-check with `git log` on 04-REVIEW.md, and record lost findings explicitly.

### Pitfall 6: CRLF false positives in the format gate
Use `npx prettier --check --end-of-line auto src index.html` on this Windows checkout, or rely on the committed-LF state.
