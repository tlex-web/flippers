### Auto-fixed Issues

**1. [Rule 3 - Blocking] The stale index stat cache made 46 refreshed files show as ` M`**
- **Found during:** Task 1 step 3. Acceptance criterion: `git status --porcelain` must equal the before-state.
- **Issue:** After `sed` stripped the CRs, `git diff` showed nothing for the 46 files, but `git status` listed all of them as ` M`. The index still cached the CRLF file size (index.html, for example, had 12560 cached against 12212 on disk). Git's `ie_modified` treats a size mismatch as "modified" without rehashing. `git update-index -q --refresh` ran and did not clear it, because it takes the same shortcut. The research's verified recipe (`rm` + `git checkout --`) avoided this, but the plan bans checkout.
- **Fix:**
  1. Proved that `git hash-object -- P` equals the index oid for all 46 paths (46 identical, 0 mismatches).
  2. Ran `git add -- P` for exactly those 46 paths. This is not `--renormalize`, and the user-edited files were never included. The plan's Task 1 ban list is checkout, restore, reset, stash and `add --renormalize`.
  3. Confirmed `git ls-files -s` was byte-identical before and after that add: no mode, oid or path changed.
  4. Confirmed `git diff --cached --name-only` was empty before `.gitattributes` was staged.
- **Files modified:** none. Index stat data only.
- **Verification:** `git status --porcelain` is identical to the before-state. The user's STATE.md and config.json diff is unchanged. The commit contains only `.gitattributes`.
