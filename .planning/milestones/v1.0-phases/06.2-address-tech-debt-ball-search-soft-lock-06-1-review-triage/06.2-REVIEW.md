## Warnings

### WR-01: Search give-up removes the ball where it rests, but the drain cue and drain-apron flash fire at the drain

**File:** `src/game/game-session.ts:655-656` (consumed at `service()` 454-458; presented at `src/sandbox/presentation-observer.ts:233`)
**Issue:** After `BALL_SEARCH_KICKS` kicks that leave the ball still, `ballSearch()` sets `this.drained = this.active`. The same step's `service()` then calls `world.removeBall()` wherever the ball is resting: a hinge pocket at (0.745, 5.211), a bumper apex, and so on. `drainCount` is raised, so `PresentationObserver` pushes `"drain"` on `drainElementId` with the drain-apron flash. On screen, the ball blinks out mid-table with no animation, and the drain growl and apron flash play somewhere else (the drain sensor between x 0.86 and 2.04 at y 6.05).

The kicks before this are also silent and invisible: there is no cue, and that is open item D6 in 06.2-02-SUMMARY. A design-conscious portfolio build treats this kind of mismatch as a bug, not polish. It only happens on the fallback path, but that path exists exactly for pockets nobody has found yet, so a player who hits it will see the defect.
**Fix:** Make the give-up distinguishable from a real drain so the presentation can match it. One way:
```ts
// game-session.ts
private searchForfeits = 0;
...
} else if (this.drained === NO_BALL) {
  this.searchForfeits++;
  this.drained = this.active;
}
getBallSearchForfeitCount(): number { return this.searchForfeits; }
```
Then in `PresentationObserver.observe()`, when the forfeit count went up on this step, push a "ball lost" cue at the ball's last position instead of the apron flash. A short fade or dissolve of the ball sprite would also work. Add a search-kick coil cue keyed on `getBallSearchCount()` while you are there.

### WR-02: Sling-pinch liveness is relative to the control with no absolute floor, so it passes vacuously if the control is blind too

**File:** `src/harness/sling-pinch.test.ts:194` (also 216-226)
**Issue:** A flip counts as live when `flip.sustained >= LIVE_SPEED_RATIO * control`, where `control` is the raw no-sling speed. The control and the case under test share `DROP_X`/`DROP_Y` and the same inlane. A future geometry change that keeps the drop from reaching the bat on both specs (a moved `INLANE_Y`, a funnel or trough edit) would leave both speeds near idle. Idle-vs-idle easily satisfies `>= 0.5 x`, so liveness passes, and the `missing === 0` check only catches a ball that was removed.

That is the same vacuous-pass class 06.1-REVIEW WR-02 asked to close. The blind RED control (`BLIND_SPEC`) cannot catch it, because it blinds only the case under test and never the control. Its RED assertion (`live/FLIPS <= 0.8`) is also far looser than the measured 0/75.
**Fix:** Require an absolute launch floor, and assert the control itself is live:
```ts
/** A launched ball leaves faster than this (m/s); an idle drop never does. */
const LIVE_MIN_SPEED = 3; // pick from the measured control speeds
...
if (flip.sustained >= Math.max(LIVE_SPEED_RATIO * control, LIVE_MIN_SPEED)) live++;
...
// in the GREEN case
for (let k = K_MIN; k <= K_MAX; k++) expect(controlSpeed(id, k)).toBeGreaterThan(LIVE_MIN_SPEED);
```
Tighten the blind RED control to `live === 0` (measured 0/75) so the threshold actually separates the two cases.

### WR-03: Impossible-state guard: `resetSearch()` on tilt entry and on re-serve can never see non-zero search state

**File:** `src/game/game-session.ts:578`, `src/game/game-session.ts:986` (doc claims at 75-76, 358, 660)
**Category:** necessity
**Issue:** Neither call can find anything to reset:
- `searchKicks` changes only at 651, inside `ballSearch()`, which returns early unless `state === "tilted"` (624). Tilt entry in `onNudge` requires `state === "playing"` (557).
- `reServe()` is reached only from `backstop()`, which `service()` calls only when `state === "playing"` (450).
- A ball never goes from `"tilted"` back to `"playing"`. Tilted always leads to `"bonus"` through `service()`, then to `serveBall()`, which resets (970).
- So during `"playing"` the counter is still the 0 that `serveBall()` set. `stillSteps` is also zeroed on every non-tilted tick (624-626). At both call sites both fields are already 0.

The doc's "the kick budget resets on every serve, re-serve and tilt entry" suggests three needed resets when only the serve reset does anything. It also adds two call sites a future maintainer has to keep in sync.
**Fix:** Keep the single `resetSearch()` in `serveBall()`. Replace the other two with a one-line invariant note, for example "searchKicks only moves while tilted, and tilted always exits through serveBall". Update the class doc (75-76) and `searchKicks` JSDoc (358) to match.

## Info

### IN-01: `BALL_SEARCH_IMPULSE` is aliased to `NUDGE_IMPULSE`

**File:** `src/game/tuning.ts:196`
**Issue:** The search kick's strength was probe-validated: it frees both hinge pockets and all three apexes, and kicks in other directions re-trap 8 of 8. Because it is defined as `= NUDGE_IMPULSE`, retuning nudge feel silently changes the search kick. `ball-search.table.test.ts` would catch a regression, but it would then fail on a nudge-feel change that has nothing to do with the search.
**Fix:** Give it its own literal value, documented with the probe result, so the two can be tuned independently.

### IN-02: The give-up path is only tested on the spy rig, and never with `service()` between ticks

**File:** `src/game/game-session.test.ts` (B3, B8, B10); `src/game/ball-search.table.test.ts:191`
**Issue:** On the spy rig, B3, B8 and B10 run `r.tick(SEARCH_OUT_TICKS)` with no `service()` in between, while production calls `service()` every step. The real-table GREEN case loops until a bus drain, so it only covers the kick-frees path. If the give-up path fired there, the loop would hit `SEARCH_CAP_STEPS` with a "no bus drain" message that hides what actually happened. Nothing tests `removeBall` of a ball resting mid-table on `PlanckWorld`, or the "same step's `service()`" claim in production order.
**Fix:** Add one real-table case that runs with the search kick neutralised, for example `ballSearchSteps: 10` and a pocket the horizontal kick cannot free, or a test-only impulse of 0. Assert a forfeit with no bus drain, `liveCount` 0, and the next serve. On the spy rig, interleave `r.step()` with each tick in B3.

### IN-03: The kickback e2e no longer covers "kickback, then a real drain past the window" in the live composition

**File:** `src/sandbox/game-e2e.test.ts:1102-1138`
**Issue:** This is deliberate (06.2-04, WR-03). The case now asserts that, left alone, the kicked ball drains inside the original window (measured 783 against 1075) and is re-served by the CR-01 grace. The live-composition path from a kickback to a past-window bonus is now pinned only by the rule-level unit test. The new premise assertion also records a gameplay fact worth a look: an unaided center-post kick never keeps the ball alive past the window, so on this plunge the kickback gives nothing the backstop would not.
**Fix:** No code change required. If the kickback is meant to matter in play, record the measurement as a tuning todo for the post or kick strength.
