- **The hinge pockets:** 11 of the 800 random drops (≈1.4%) rested there, with the bats dead. The two hinge pockets are the only rests the random drops found.
- **The three bumper apexes:** (0.95, 2.133), (1.95, 2.133) and (1.45, 2.884). A dead bumper balances a ball dropped exactly over its centre. Only grid-aligned drops reached these. In live play the bumpers kick the ball off; under TILT they are dead.

No other rest exists outside `PLUNGER_ZONE`. **The longest still run (speed < 0.05 m/s outside `PLUNGER_ZONE`) of any ball that went on to drain was 114 steps.**

**Recommendation: a tilted-state ball search in `GameSession`, not a geometry change.**
- **When it fires:** while `"tilted"`, the active ball is outside `PLUNGER_ZONE` and below 0.05 m/s for `BALL_SEARCH_STEPS` = 240 consecutive ticks (2 s, 2.1× the measured 114-step worst case).
- **What it does:** the session applies a **search kick**, `NUDGE_IMPULSE` (0.15 kg·m/s), horizontally toward the playfield centre line. The kick is velocity only, through the existing `applyImpulse`.
- **Fallback:** after `BALL_SEARCH_KICKS` = 2 kicks fail, it records the ball as drained. The tilted drain path then forfeits the ball, which is exactly what TILT already promises.

Why a kick toward the centre:
- It frees every pocket found: the hinge pockets drain in **101 steps**, the bumper apexes in 247-324.
- Up, down and away impulses all re-trap the hinge ball (8/8 re-rested).

### Pattern 1: Tilted-only ball search in `GameSession.tick()`

**What:** A step-counted stillness timer on the active ball, live only in `"tilted"`. It applies a search kick, then falls back to a forfeit drain.

**Why `tick()`:** it is the pre-step seam where `onNudge` already applies impulses ("Call it at the top of a fixed step (between steps, as the `applyImpulse` contract requires)", game-session.ts:508-509). The fallback sets `this.drained`, which the same step's `service()` consumes on the existing tilted path. That gives a forfeit tally, the drain counter (and therefore the drain cue), and the next serve. No new state is needed.

**Reset rules:**
- Clear `stillSteps` whenever the state is not `"tilted"`, there is no active ball, the ball is in `PLUNGER_ZONE`, or its speed is at or above the threshold.
- Clear the kick budget on every serve, re-serve and tilt entry.
- Read only the **active** ball. `getBalls()` may hold untracked balls, as in the spy rig's `extraBallIds`.

**Option (mirrors `ballSaveSteps`, game-session.ts:195):** `readonly ballSearchSteps?: number`. The default is `BALL_SEARCH_STEPS`, and **0 disables it**. That gives the RED control and a way out for any legacy test.

**Example:** this is the prototype that was run, tightened to project style [code shape ASSUMED; values VERIFIED by probe]:
```ts
// src/game/tuning.ts — Ball search (tilted soft-lock, 06.2)
/** Still steps (240 = 2 s) before a tilted ball is searched. Probe: the longest
 *  still run of any ball that went on to drain was 114 steps (1,077 dead-bat drops). */
export const BALL_SEARCH_STEPS = 240;
/** "Still" speed (m/s); a pocketed ball sleeps at 0. Same scale as PLUNGER_REST_SPEED_EPS. */
export const BALL_SEARCH_SPEED_EPS = 0.05;
/** Search kick (kg·m/s), horizontal toward PLAYFIELD_CENTER_X; = NUDGE_IMPULSE.
 *  Probe: frees the hinge pockets (drain in 101 steps) and the bumper apexes. */
export const BALL_SEARCH_IMPULSE = NUDGE_IMPULSE;
/** Search kicks before the ball is given up as drained (a tilted ball is forfeit anyway). */
export const BALL_SEARCH_KICKS = 2;

// src/game/game-session.ts — called last in tick()
private ballSearch(): void {
  if (this.state !== "tilted" || this.active === NO_BALL || this.searchSteps <= 0) {
    this.stillSteps = 0;
    return;
  }
  const b = this.activeBall();                 // loop over getBalls(), no allocation
  if (!b) return;
  const z = PLUNGER_ZONE;
  const inZone = b.x >= z.minX && b.x <= z.maxX && b.y >= z.minY && b.y <= z.maxY;
  if (inZone || Math.hypot(b.vx, b.vy) >= BALL_SEARCH_SPEED_EPS) { this.stillSteps = 0; return; }
  if (++this.stillSteps < this.searchSteps) return;
  this.stillSteps = 0;
  if (this.searchKicks < BALL_SEARCH_KICKS) {
    this.searchKicks++;
    this.searchCount++;                        // presentation counter (getBallSearchCount)
    const dir = b.x < PLAYFIELD_CENTER_X ? 1 : -1;
    this.world.applyImpulse(b.id, dir * BALL_SEARCH_IMPULSE, 0);
  } else {
    this.drained = this.active;                // service() → tilted forfeit → next ball
  }
}
```

### Anti-Patterns to Avoid
- **A positional drain test (`y > DRAIN_Y`) as the fallback.** This is exactly 03-REVIEW CR-01 (game-session.ts:64-68): the parked plunger ball sits below the drain line. The fallback must be stillness + `"tilted"` + outside `PLUNGER_ZONE`, never position.
- **Running the ball search in `"playing"`.** A cradled ball is still for as long as the player holds the key, so the search would knock it off. Probe 3 shows no live-play soft-lock exists.
- **Injecting a synthetic `CollisionEvent` into the router.** The bus is physics truth. Set `this.drained` directly; the drain cue already keys on `getDrainCount()` (presentation-observer.ts:154, 177).

## Common Pitfalls

### Pitfall 1: The ball search fires on a cradle or a legitimate pause
**What goes wrong:** the ball is knocked off a flipper the player is holding.
**How to avoid:** run the search only in `"tilted"`, where the flippers are dead. The 240-step threshold is 2.1× the longest measured pre-drain still run (114).
**Warning signs:** any `"playing"` test that records an impulse it did not ask for.

### Pitfall 2: The spy rig's balls are "still" by default
**What goes wrong:** game-session.test.ts `spyBall` returns `{ id, x, y: 0, vx: 0, vy: 0, ... }`, which is outside the zone and at rest. Any tilted test that ticks 240 or more steps now records search impulses. The prototype passed every existing case, but new tilted cases must expect the search or pass `ballSearchSteps: 0`.
**How to avoid:** use the option. Assert `impulses` explicitly in the new describe.

### Pitfall 3: The fallback reintroduces the CR-01 parked-ball bug
**What goes wrong:** a ball resting on the plunger, which is below `DRAIN_Y`, gets "drained".
**How to avoid:** exclude `PLUNGER_ZONE`; the plunger stays live in tilt (game-session.ts:12-13). Add a unit case: tilted with the ball in the zone, still for 1,000 steps → no impulse, no drain.

### Pitfall 4: The search kick feeds nudge or tilt presentation
**What goes wrong:** a cabinet shake or a WARNING appears on a machine action.
**How to avoid:** use separate counters (`getBallSearchCount()`), and leave the tilt meter and `nudgeCount` alone. No cue is required this phase (Open Question 2).

### Pitfall 5: Re-authoring WR-03 into a new brittle premise
**What goes wrong:** asserting exact step numbers (534/783) or the 9-step-margin grace-floor relation.
**How to avoid:** assert only the premises the case needs (the drain lands inside the original window), and put the measured numbers in the assertion messages.

### Pitfall 6: The IN-04 refresh destroys uncommitted work
**How to avoid:** refresh only files where `git diff --quiet -- "$f"` holds. Never use `reset --hard`.

### Pitfall 7: WR-01 visual drift
The arrow moves from x 0.585 to 0.4645, which is the passage centre at the sensor line (0.069..0.86). The user is design-conscious and accepted the current look once (06.1-UAT test 1). Gate the change on a `checkpoint:human-verify` with `npm run dev` and `?debug=1`.
