- **WR-02 fixed.** `inlaneFlip` returns `{ sustained, missing }` and no longer maps an absent ball to speed 0. `sweep()` replaces `worstRatio` and reports `worst`, `live` and `missing`. The GREEN cases assert all three. Measured this run on TABLE_SPEC:

  BLIND passes the old ratio-only check (the vacuous pass 06.1-REVIEW WR-02 described) and fails liveness, so the new check has teeth. The file runs six cases: two GREEN, two old-sling RED controls and two walled-off RED controls. All six pass, in about 6 s.
- **WR-03 fixed.** The three `KICKBACK_CRADLE_*` constants, their search-provenance JSDoc and the cradle input block are gone. Everything from `makeGame()` through the one-step-later block is unchanged. The new tail uses no player input after the launch. It asserts the window premise (drain <= exit + BALL_SAVE_STEPS) with the live and measured numbers in the message. It then asserts the full CR-01 grace outcome and that the re-served ball's drain enters `"bonus"`. Measured this run: **chute exit at session step 235, kick at 534, drain at 783, window end 1075.** After that drain the game is still `playing` on ball 1, with saves 1, reserves 1, kind `kickback` and a new active id. These numbers match research Pattern 4 exactly.
- **Gameplay change recorded (06.1 review WR-03).** Since the 06.1 sling move (slings 0.35 m up-table), a kicked-back ball left alone drains at about session step 783. That is inside the original save window (ends at 1075), so the CR-01 kickback grace backstops it: the same ball number is re-served on the plunger, and the save count stays at one (the kickback). Before 06.1 the unaided kicked ball survived past the window, and its drain was real. The rule "a kickback, then a real drain past the original window, enters bonus" stays pinned at rule level by the game-session.test.ts case "a kickback never makes a drain inside the original save window cost the ball ..." (`lastWindowStep + 1` goes to `"bonus"`). That case passes.
