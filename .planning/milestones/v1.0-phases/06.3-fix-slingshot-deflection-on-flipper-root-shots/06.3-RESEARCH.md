## Architecture Patterns

### Data flow (shot-clearance gate)
```
TableSpec variant (TRIMMED | PRE_TRIM | NO_SLING | BLIND)
  -> new PlanckWorld({ table })  --resolve()-->  colliders + ResolvedElement[] (kickFace carried)
  -> CollisionRouter(world)  -> listener 1: ReactiveElements (ALWAYS_LIVE gate; kicks in service())
                             -> listener 2: first-contact recorder (elementKind === "slingshot", armed at flip)
  -> FixedStepLoop.advance(FIXED_DT*1000, drive, onPostStep = dispatch(); service())
  -> settle 30 droop steps -> addBall (rest-grid placement | inlane drop) -> k droop steps
  -> measure d = (ball - pivot) . (cos a, sin a)   -> classify: root (<0.25) | gated [0.25, 0.45] | off-tip (>0.45)
  -> raise up to 60 steps -> PASS iff y <= 3.85 && vy < 0 before any gated sling contact
```

### Pattern 1: explicit kick face (D-09). Recommended mechanism
**What:** an optional `kickFace?: number` on `PolylineSpec`: the index into the resolved `segments` (segment i runs vertex i → i+1; for a loop the last index is the closing segment). `resolve()` validates it and carries it as `kickFace: number | null` on `ResolvedElement`. `deriveKickFace` uses it when it is non-null.

**Why it survives mirroring:** `mirrorPath` "Path order is kept, so the mirrored chain traverses the reflected points in the same sequence" [VERIFIED: spec.ts:170-175], and `resolvePolyline` builds `segments.push({ a: vertices[i], b: vertices[i + 1] })` then the closing `{ a: vertices[vertices.length - 1], b: vertices[0] }` [VERIFIED: resolve.ts:197-203]. For `[top, lowerLeft, corner]`, segment 0 is the inlane edge, 1 the lower face and **2 the hypotenuse corner→top**, the same index for 301. The centroid-based normal orientation already gives the outward normal. Check at t = 0.28: centroid (0.888, 4.184), mid-face minus centroid (0.014, −0.208), and n = (0.9487, −0.3162) gives a positive dot.

**In-repo values (verbatim):**
- `src/table/spec.ts:61-66`: `export interface PolylineSpec extends ElementBase { readonly kind: Exclude<ElementKind, "flipper">; readonly path: readonly PathNode[]; readonly loop?: boolean; readonly sensor?: boolean; }` [VERIFIED]
- `src/table/resolve.ts:43-68`: `ResolvedElement` fields `id, kind, vertices, loop, segments, circle, sensor, mount`. Built only in `resolve()` (lines 234-243, 249-258, 261-270); no hand-made literal exists in `src/` (grep). `resolve.test.ts` asserts per-field (`:97 circle toEqual`, `:105 mount toEqual`), never the whole object, so a new field breaks no `toEqual` [VERIFIED: grep plus read of resolve.test.ts:80-110]
- `src/game/reactive-elements.ts:175-213`: `deriveKickFace` loops `el.segments` for `bestLen`, then the centroid flip `if (nx * (mx - cx) + ny * (my - cy) < 0)` [VERIFIED]

**Validation (fail loud, threat T-03-01 style, `fail(el, reason)` at resolve.ts:70-72):** if `kickFace` is set, it must be an integer, 0 ≤ i < segments.length, on `kind === "slingshot"`. Recommended extra: `resolve()` fails a `slingshot` with **no** `kickFace`, and the longest-segment rule is deleted. Cost: add `kickFace: 2` to `table-world.test.ts:421-422` (the only slingshot literals besides spec.ts; the sling-pinch spreads inherit it). This removes the silent fallback that caused D-09. ### Pattern 2: corner on the hypotenuse, exactly
Write the corner as a lerp from the top vertex, so the normal stays (0.9487, −0.3162) by construction (D-08). At t = 0.28 the decimals are exact: `{ x: 0.944, y: 4.102 }` (0.86 + 0.3·0.28, 3.85 + 0.9·0.28). Either form works; a named `SLING_TRIM` fraction documents intent.

### Pattern 3: RED-then-GREEN geometry proof (06.1-02 / 06.2-04 idiom)
GREEN on TABLE_SPEC (all-of). A RED control on the pre-trim geometry (must fail). A NO_SLING control (must pass, proves the criterion is reachable). A liveness floor (kept flips per bat ≥ pinned count) plus a BLIND control (inlane walled off, reusing `sling-pinch.test.ts:81-91`'s wall), which must fail liveness. Every flip goes through `FixedStepLoop` with motor commands latched in the pre-step hook.

### Anti-Patterns to Avoid
- **Using `ReactiveSoakWorld` for first-contact detection.** Its `drainEvents()` always returns `NO_EVENTS` ("always empty, because the rules consume the inner world's events internally through the router"), and it hard-wires `table: TABLE_SPEC` [VERIFIED: reactive-world.ts:54-58, 72, 147-149]. CONTEXT's pointer to "`reactive-world.ts` `drainEvents()`" would yield a gate that never sees a contact. Build the rig from `PlanckWorld({ table })` plus `CollisionRouter` plus `ReactiveElements`, and record via `router.register(...)`, as `reactive-table.test.ts` `makeRig` does.
- **Calling `world.drainEvents()` directly while a `CollisionRouter` is wired.** The router "drains it exactly once per `dispatch()`" [VERIFIED: collision-router.ts header]. A second drainer steals events from the rules.
- **Silently narrowing the band** to dodge cross shots. Forbidden by D-07.
- **Hand-placing the rubber stroke** for the shorter face. D-10 requires everything to keep reading `deriveKickFace`.

## Common Pitfalls

### Pitfall 1: the locked gate is unreachable (cross shots)
**What goes wrong:** the all-of "no contact with 300/301" gate fails 30/94 at every trim.
**Why:** cross shots (d ≥ 0.35 inlane, d ≥ 0.42 rest) cross the opposite sling's lower-face and lower-left region, which the trim cannot move.
**How to avoid:** settle the gate scope with the user before writing the test (see Open Question 1).
**Warning signs:** an executor tweaking the band, the corner or the 60-step window until it passes.

### Pitfall 2: no upper d cap, so NO_SLING fails liveness
The inlane sweep's late flips (k ≥ ~100) catch a ball at d 0.48–0.65 that is rolling off the tip, and they time out even with no slings. Cap kept flips at d ≤ 0.45.

### Pitfall 3: `process.env.MODE` is `"test"` under vitest
Any probe or test that switches behaviour on an env var named `MODE` silently takes the wrong branch (it bit this research's first probe run). Use a distinctive name, or none.

### Pitfall 4: console metrics may not appear under the default reporter
D-06 asks to "print" the root-strip share. In this checkout a passing test's `console.info` did not appear under the default reporter on one run and did appear on another. It appeared reliably with `--reporter=verbose` [VERIFIED: scratch test, removed]. Print the metric with `console.info`, put it in the assertion message too, and capture evidence with `npx vitest run src/harness/root-shot.test.ts --reporter=verbose`.

### Pitfall 5: name collision `OLD_LEFT_SLING`
`sling-pinch.test.ts:42` already declares `OLD_LEFT_SLING` (pre-06.1 geometry). Use a new file, or `PRE_TRIM_LEFT_SLING`.

### Pitfall 6: the D-09 guard needs a real RED
On today's TABLE_SPEC the longest-segment rule already picks the hypotenuse, so a guard that only checks today's TABLE_SPEC passes before any change. Make the guard RED first. Either assert that resolved 300/301 carry a non-null explicit `kickFace`, or evaluate a locally trimmed fixture (`{ ...e, path: trimmed }`), where the longest rule picks the 0.75 m inlane edge (nx < 0) at t = 0.28. There the lower face is 0.505 m and the hypotenuse 0.266 m.

### Pitfall 7: line endings and format
`.gitattributes` is `* text=auto eol=lf` and `.prettierrc.json` sets `endOfLine "lf"` (06.2-01). Both target files are `i/lf w/lf` [VERIFIED: `git ls-files --eol`]. ### Gate rig (adapted from this session's working probe)
```typescript
// Source: this session's gate.probe.ts (ran green as a probe); APIs from
// src/app/collision-router.ts, src/game/reactive-elements.ts, src/sim/loop.ts:85
const LIVE: RulesGate = { isLive: () => true, award: () => undefined };

function shot(table: TableSpec, id: 0 | 1, mode: "rest" | "inlane", d: number, k: number) {
  const world = new PlanckWorld({ table });
  const router = new CollisionRouter(world);
  const reactive = new ReactiveElements(world, router, LIVE); // rules first (main.ts order)
  let armed = false;
  let first: { id: number; x: number; y: number } | null = null;
  router.register((e) => {
    if (armed && !first && e.elementKind === "slingshot") first = { id: e.elementId, x: e.point.x, y: e.point.y };
  });
  const loop = new FixedStepLoop(world);
  const post = (): void => { router.dispatch(); reactive.service(); };
  const droop = (): void => { world.setFlipperMotor(0, -1); world.setFlipperMotor(1, -1); };
  const step = (drive: () => void): void => { loop.advance(FIXED_DT * 1000, drive, post); };
  for (let i = 0; i < SETTLE_STEPS; i++) step(droop); // 30
  const f = world.getFlippers()[id]!;
  const ux = Math.cos(f.angle), uy = Math.sin(f.angle);   // along the bat, both bats
  let nx = uy, ny = -ux; if (ny > 0) { nx = -nx; ny = -ny; } // up-normal of the top surface
  if (mode === "rest") {
    const off = FLIPPER_HALF_WIDTH_M + BALL_RADIUS_M + 0.002;
    world.addBall({ x: f.pivotX + d * ux + off * nx, y: f.pivotY + d * uy + off * ny, vx: 0, vy: 0, radius: BALL_RADIUS_M });
  } else {
    world.addBall({ x: id === 0 ? 0.6 : 2 * PLAYFIELD_CENTER_X - 0.6, y: 4.5, vx: 0, vy: 1.0, radius: BALL_RADIUS_M });
  }
  for (let i = 0; i < k; i++) step(droop);
  const b0 = world.getBalls()[0]!, f0 = world.getFlippers()[id]!;
  const along = (b0.x - f0.pivotX) * Math.cos(f0.angle) + (b0.y - f0.pivotY) * Math.sin(f0.angle);
  armed = true;
  const raise = (): void => { world.setFlipperMotor(id, 1); world.setFlipperMotor(1 - id, -1); };
  for (let i = 0; i < 60; i++) {
    step(raise);
    const b = world.getBalls()[0];
    if (!b) return { along, pass: false, first };
    if (b.y <= 3.85 && b.vy < 0) return { along, pass: first === null /* or own-only, per Q1 */, first };
  }
  return { along, pass: false, first };
}
```
Constants verified this session: `BALL_RADIUS_M = 0.2`, `FIXED_DT = 1 / 120`, `FLIPPER_HALF_WIDTH_M = 0.07`, `FLIPPER_LENGTH_M = 0.5` [VERIFIED: constants.ts:48,85,114,123]. `PLAYFIELD_CENTER_X = 1.45` [VERIFIED: spec.ts:163]. The right bat's rest angle is ≈ 2.75 (types.ts doc), so `(cos a, sin a)` points from the pivot toward the tip for both bats. `ReactiveElements` takes `(world, router, gate, feedback?, hooks?, config?)` [VERIFIED: reactive-elements.ts:286-293]. The real `PlanckWorld` satisfies `ReactiveWorld` directly.

**Runtime:** a full GREEN + RED + NO_SLING + BLIND evaluation is about 4 × 0.7 s. Use the `vi.setConfig({ testTimeout: 30_000 })` idiom of the heavy suites.
