# Phase 06.4.1 Plan 02: Procedural SVG favicon and RND-01 one-icon carve-out Summary

**An inline SVG data-URI favicon (magenta bumper cap in a cyan ring on the space background, all palette.ts colors) in index.html head, admitted by a narrow validate-and-strip carve-out in the RND-01 asset gate that still rejects every other icon, icon file and data: URI**

## Accomplishments

- The tab now gets a branded icon, and the browser has no reason to request `/favicon.ico`. The icon is a 32x32 rounded square in BG_BOTTOM `#0b0420`, with a WALL `#4cc9f0` ring (r 11, stroke 2.5) and a BUMPER_CAP `#f72585` disc (r 6) in the middle. These are the HUD's cyan and magenta. It is one `<link>`, with no file, no `public/` directory and no JS.
- The RND-01 gate admits exactly this one icon and nothing else. `stripProceduralIcon` requires exactly one link of the exact shape (rel, type, href in that order). It decodes the SVG, and `validateIconSvg` checks it: the xmlns prefix, no fetch/script/style tokens, no http outside the xmlns, paint values `none` or a palette hex, and every `#hex` a palette hex. Only then is the link stripped, and the unchanged PATTERNS scan the rest.
- The build keeps the href inline. dist/index.html has one `rel="icon"` with the data URI, and dist contains no .svg, .ico or .png file.
