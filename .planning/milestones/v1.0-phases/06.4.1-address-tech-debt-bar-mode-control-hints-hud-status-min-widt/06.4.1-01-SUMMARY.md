# Phase 06.4.1 Plan 01: Bar-mode control hint and HUD status reserve Summary

**A CSS-only "Hold Space to launch · ← → flip" hint in the bar's status cell (visible only while the status is empty), a 23-character width reserve on the side-panel status line so GAME OVER keeps the 16 px clearance, and the bar's Mute row kept by class**

## Performance

- **Duration:** 9 min
- **Started:** 2026-11-24T19:07:23Z
- **Completed:** 2026-11-24T19:16:30Z
- **Tasks:** 2
- **Files modified:** 4

## Accomplishments

- Narrow-window players now see how to play. In bar mode the status row shows a muted 12 px "Hold Space to launch · ← → flip" whenever the status line is empty (after Enter and during play). Any status text (PRESS ENTER, TILT, WARNING, BALL SAVED, SKILL SHOT, BONUS, GAME OVER, NEW HIGH SCORE) hides it. It is hidden with visibility, so the bar keeps one height and the table does not move.
- The side panel is now as wide at boot as it gets in any state. The status line reserves the width of "GAME OVER · PRESS ENTER", so the one measurement `applyView` takes at boot still holds at game over. Viewports around 1084-1148 wide at 900 tall that used to overlap at GAME OVER now get the bar.
- The bar hides the controls list by class, so reordering the list can no longer hide the Mute row by accident.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 3 - Blocking] KEY_CODE typed `as const`**
- **Found during:** Task 1 GREEN verify
- **Issue:** `Readonly<Record<string, string>>` indexing returns `string | undefined` under `noUncheckedIndexedAccess`, so tsc failed (TS2345) when it was passed to `ev()`.
- **Fix:** Made `KEY_CODE` a literal object `as const`.
- **Files modified:** src/ui/hud-layout.test.ts
- **Verification:** `npx tsc --noEmit` clean
- **Committed in:** 7d78f03

**2. [Rule 3 - Blocking] Hint-adjacency test asserts on a one-line extract**
- **Found during:** Task 1 RED evidence capture
- **Issue:** The behavior regex was written as `expect(indexHtml).toMatch(...)`. On failure Vitest's TAP reporter prints the whole index.html as an unindented multi-line `actual`, so the RED-evidence classifier rejected the report as malformed TAP.
- **Fix:** Capture the tag right after the empty status div with `/id="hud-status"[^>]*><\/div>\s*(<[^>]*>)/` and `toBe('<p class="hud-hint">')`. This means the same thing as the plan's regex (empty status div, hint as the next sibling) and gives a one-line failure message.
- **Files modified:** src/ui/hud-layout.test.ts
- **Committed in:** 0871b0f (RED commit)

**3. [Minor] hud.test.ts comment placed above the `none` row instead of trailing it**
- Two-line comment, which Prettier keeps stable; no logic change.
