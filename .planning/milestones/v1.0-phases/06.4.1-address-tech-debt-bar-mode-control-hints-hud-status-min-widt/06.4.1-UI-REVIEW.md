## Top 3 Priority Fixes

1. **The bar hint shows after the ball is launched** (WARNING). Under A1 = A the hint appears whenever the status is empty, which includes every moment of active play. "Hold Space to launch" is then misleading, and the line permanently occupies the status row. The user approved this scope, so it is a follow-up, not a regression. Fix: hide the hint once the ball is in play, for example a `data-` flag set from the existing status/HUD update path, or show it only in the ready state. This needs a small JS change, so it is a judgment call against the render/DOM-only boundary.
2. **The 11 px label type is still open** (WARNING, carried from 06.4 fix 2). It is at index.html:157, :288 and :347. Raise labels to 12 px, which the scale already uses, so the scale loses one size.
3. **The hint depends on `.hud-status:not(:empty)`** (WARNING, fragile coupling). index.html:125 hides the hint only while the status element is truly empty. Any whitespace text node or a placeholder written to `#hud-status` would permanently hide the hint. hud.test.ts documents the coupling, but nothing pins what the DOM sink writes for `none`. Fix: add a test that the sink writes `""` (not `" "`) for `none`, or switch to a `data-status` attribute.

Minor recommendations:
- The hint `<p>` has no `aria-hidden` or live-region attribute. It is static, so it is read once in DOM order after the status. Acceptable.
- In bar mode the hint is 12 px beside a 16 px status line. The size change on handover is intentional, but check it by eye at 375 px if the type scale changes.
- The favicon at 16 px is a 6 px-radius disc inside an 11 px ring. The user approved it at the tab size, and the SVG has no `sizes` attribute, which is fine for a single vector icon.

## Detailed Findings

### Pillar 1: Copywriting (3/4)
- New string at index.html:392: "Hold Space to launch · ← → flip". It is terse, imperative and names live bindings. hud-layout.test.ts pins Space, ArrowLeft and ArrowRight against src/input.
- Deduction: the string is wrong in the post-launch state. The ball is already launched while the status is empty during play, so "Hold Space to launch" repeats the plunger instruction for the whole ball.
- No generic labels were added. Status strings are unchanged.

### Pillar 2: Visuals (3/4)
- The hint is `--text-muted` at 12 px with kbd caps matching the side-panel controls list (index.html:244-255), so it is one visual language across both modes.
- Sharing one grid cell by `visibility: hidden` means no layout shift. The status cell has a single occupant at any time.
- The favicon (index.html:8) is a bumper cap in a cyan ring on a BG_BOTTOM square. It is on theme and uses no raster file.
- Deduction: the hint is the faintest text in the bar, and legibility at 375 and 320 px rests on the user's "approved" with no recorded numbers. The cell has `text-overflow: ellipsis`, so at 320 px the hint may truncate to "Hold Space to launch · ← →…", which hides "flip". This was not measured here.

### Pillar 3: Color (4/4)
- The hint adds no color. It reuses `--text-muted` and the existing kbd border and background.
- The favicon colors are #0b0420, #4cc9f0 and #f72585. asset-free.test.ts imports palette.ts at run time and rejects any other hex, so the icon cannot drift.
- The accent stays on the status magenta. The hint is intentionally not accented.

### Pillar 4: Typography (3/4)
- Sizes in use: 11, 12, 16 and 32 px, and weights 400 and 700. The phase adds none.
- The status reserve (index.html:214) is tied to the monospace advance plus letter-spacing, `calc(23 * (1ch + 0.12em))`. It is pinned to `statusText` by an exhaustive `Record<StatusCode, number>` test, so a longer status will fail a test.
- Deduction: 11 px labels remain (see fix 2).

### Pillar 5: Spacing (4/4)
- The hint's `line-height: 1.6` at 12 px equals the status's `1.2` at 16 px (19.2 px). The row height is unchanged, and the bar stays at the 102 px measured in 06.4.
- `margin: 0` on the hint prevents the `<p>` default margins from growing the row. `min-width: 0` keeps it from widening the grid at 320 px.
- The side-panel reserve fixes 06.4 WR-02. The band around vw 1084-1148 at vh 900 that overlapped at GAME OVER now switches to the bar, so the 16 px clearance holds. The user approved it at ~1100 and ~1150.
- The bar resets `min-width: auto` (index.html:104), so the reserve does not widen the bar row.

### Pillar 6: Experience Design (3/4)
- 06.4 fix 1 is addressed. A keyboard player on a narrow viewport now sees the plunger and flipper keys, and the hint hides under any status without moving the table.
- CSS-only state: no JS and no layout read were added, so RND-02 holds. Determinism replays and apply-view are green per 06.4.1-03.
- Fix 3 is addressed. The inline SVG icon removes the only console error from 06.4, and the build ships no icon file. The RND-01 gate admits exactly one icon with a palette-only payload, backed by 29 negative cases.
- Deductions: the post-launch hint (fix 1), the `:empty` coupling (fix 3), and no touch input, which is out of scope. The 06.4 IN-01 overflow below about 345 px is still open and was not re-measured here.
