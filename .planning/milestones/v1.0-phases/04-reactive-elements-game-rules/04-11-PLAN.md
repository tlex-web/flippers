<objective>
Close G-04-11 (major). On all six bindings, each bat must answer its key, and no lost
keyup may leave a bat hanging raised.

Root cause (binding, from .planning/debug/left-shift-sticky-keys-flipper-stuck.md):
FlipperInput builds its held set only from keydown/keyup pairs, plus a force-clear on window
blur and on a hidden tab. Nothing re-checks that set afterwards. When Windows takes a Shift
keyup, the stale ShiftLeft keeps the whole left side held. Two ways this happens: a keydown
handled after the Sticky Keys prompt's blur sends its keyup to the dialog, or Sticky Keys
gets turned ON. Once the side is stuck, Z and Left Arrow cannot release the bat, a new
ShiftLeft keydown is de-duped, and the flipper gate re-raises the bat on every serve. The
right side behaves the same with ShiftRight. The input layer and the FSM are correct
whenever keydown and keyup arrive in pairs (headless S1-S7).

Mechanism (removes the code half of the AND-gate). Two self-checks are added to the held set:
1. Window focus regain force-clears it (Task 1). The window focus event only ever follows a
   blur, and the blur already cleared every key held before it. So this clear can only drop
   keydowns that arrived while the window was blurred, which are exactly the stale ones.
2. Any later non-Shift key event that reports shiftKey === false drops a held ShiftLeft or
   ShiftRight (Task 2). The OS's modifier state proves no Shift is down. Shift-key events
   never reconcile, so the both-Shift cradle is safe from platform differences in how the
   remaining Shift is reported.

Edges come from each event's net per-side transition. A stale-Shift drop plus the new key's
add (for example Z over a stale ShiftLeft) therefore produces no edge, and the bat does not
drop under the player's finger.

Purpose: FLIP-01 (keyboard flippers that always respond) and GAME-02 (the serve no longer
re-raises a stale bat). Bindings, feel constants, the FSM and the Planck adapter are not
touched.
Output: two self-heal paths in FlipperInput, plus regression tests at the unit, keyboard-to-Planck
and full-game levels.
</objective>
