<objective>
Close G-04-21 (major). User decision A in UAT test 21: fix review findings WR-01 and WR-02 now, and do not accept them as residuals. IN-01 rides along.

Root cause (binding, from the G-04-21 root_cause and 04-REVIEW.md):
- WR-01: isSecondShiftPress accepts a repeat-flagged Shift keydown only when the OTHER Shift code is in held. forceClear (blur, focus regain, hidden tab) empties held. A player holding one Shift across a clear (the Sticky Keys prompt, or a Shift+click that steals focus) then presses the other Shift. Windows flags that genuine press repeat:true (the VK_SHIFT merge), so it fails the held check and is dropped. Until every Shift is released, neither Shift can raise a bat.
- WR-02: handleKeyDown also runs dropStaleShift. With the heal on, the Shift-code exemption is gone, so a ShiftLeft/ShiftRight KEYDOWN reporting shiftKey:false deletes the other held Shift and drops its bat. The documented contract is keyup only.

Mechanism (per the review fix, chosen by the user):
1. WR-01: remember which Shift code the ignored Shift auto-repeats carried since the last clear (repeatingShift). A repeat-flagged keydown for the OTHER Shift code is then a new physical press, even when held is empty. The marker resets in forceClear and on a Shift keyup reporting shiftKey false.
2. WR-02: dropStaleShift takes isKeyUp. A Shift key's own event reconciles only on keyup with the heal on. handleKeyDown passes false and handleKeyUp passes true.
3. IN-01: one comment in main.ts.

Purpose: FLIP-01 (every binding answers its key, including after a focus change) and GAME-02 (the serve's flipper-gate re-press reads an isHeld that WR-02 can no longer corrupt).
Output: two small logic changes in FlipperInput, header and docs with the residual, unit and keyboard-to-Planck regressions, and one main.ts comment.
Out of scope: resolved gaps G-04-6, G-04-10, G-04-11 and G-04-17; review findings IN-02, IN-03 and IN-04; physics; styling; bindings.
