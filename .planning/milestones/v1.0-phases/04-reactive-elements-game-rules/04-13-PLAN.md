<objective>
Close the hint half of G-04-17. UAT test 18 recorded the user's decision A: keep Left and
Right Shift as default flipper bindings, and add a controls-list hint naming the most
reliable keys on Windows. The user's keyboard is German QWERTZ (layout 00000407), where the
KeyZ key is printed Y and the Slash key is printed -. A literal "Z, /" hint would therefore
point at the wrong keys. The controls list already shows Z and /, which is the same defect.

Mechanism. The layout-dependent key caps carry their KeyboardEvent.code in a data-code
attribute, with the US label as the markup fallback. At boot, main.ts calls initKeyLabels.
It asks navigator.keyboard.getLayoutMap() (Keyboard Map API: Chromium only, secure context,
blocked in cross-origin iframes) for the printed character of each code, and rewrites each
cap's text. The Windows note always names the arrow keys, which read the same on every
layout. Its KeyZ and Slash caps sit in a data-layout-only span that is unhidden only when
every cap resolved. On a browser without the API, the note therefore names only keys it can
vouch for.

Why the residual needs a hint: plan 04-12 heals the both-Shift merge, but one window remains
that no browser can see. On Windows, a bat whose Shift is released while the other Shift is
still held stays up until the other Shift is released. The Sticky Keys residual (T-04-29) is
unchanged. The note steers Windows players to the keys that have neither problem.

Purpose: FLIP-01 (players can find the bindings that work) and GAME-01 (the HUD controls
list is correct for the player's keyboard).
Output: a small engine-free src/ui module with tests, data-code caps plus the note in
index.html, and a one-call boot wiring in main.ts.
</objective>

TypeScript 5.9.3 lib.dom has no Keyboard Map API types (navigator.keyboard is absent), and HTMLElement.hidden is boolean.
Weak-type note: navigator has no property in common with an all-optional { keyboard?: ... } interface, so TypeScript rejects that argument type (TS2559). readLayoutMap and initKeyLabels therefore take the navigator as unknown and narrow at runtime.
Vitest (environment node) resolves `?raw` imports of index.html. This was verified in planning with a scratch Vitest run against this repo's index.html. node_modules/vite/client.d.ts declares the module '*?raw'. There is no @types/node, so node:fs is unavailable in tests.
