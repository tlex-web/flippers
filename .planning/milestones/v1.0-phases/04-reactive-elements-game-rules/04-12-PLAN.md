<objective>
Close the input half of G-04-17 (minor): the Shift bindings must work as reliably as
the arrow keys in a both-Shift hold on Windows. Also fix review finding WR-01, which the
new release heal can trigger.

Root cause (binding, from the G-04-17 root_cause and .planning/debug/shift-flipper-residual-stick.md):
Windows posts both Shift keys as one virtual key (VK_SHIFT), and FlipperInput throws away
both event-level traces of that.
1. Press. The second Shift pressed while the other is held arrives as a keydown with
   repeat:true, flagged by the OS (still true 2.6 s later). handleKeyDown drops every repeat,
   so in a both-Shift hold the second-pressed bat never rises.
2. Release (WR-02). The first Shift released while both are held sends NO keyup. Only the
   last release fires, carrying shiftKey:false. dropStaleShift returns early for Shift-key
   events (04-11 design, pinned by test B6), so the first-pressed Shift stays in held.

The bat sticks only when the first-pressed Shift is also released first, which is why the
user saw it "sometimes". It clears on a lone re-tap, any non-Shift key or a focus change.
Otherwise the flipper gate re-presses it on the next serve. Live-captured page sequences
(Chrome 157 / Windows 11, the user's machine):
- A, keys LD RD LU RU: D:ShiftLeft s1 r0, D:ShiftRight s1 r1, U:ShiftRight s0
- B, keys LD RD RU LU: D:ShiftLeft s1 r0, D:ShiftRight s1 r1, U:ShiftLeft s0
- C, keys LD LU: D:ShiftLeft s1 r0, U:ShiftLeft s0
- D, keys RD LD LU RU: D:ShiftRight s1 r0, D:ShiftLeft s1 r1, U:ShiftRight s0
- E: the same as A with a 2600 ms gap before RD
- F, keys LD RD LU LD LU RU: D:ShiftLeft s1 r0, D:ShiftRight s1 r1, D:ShiftLeft s1 r1, U:ShiftRight s0
- D' (symmetry of B, not captured), keys RD LD RU LU: D:ShiftRight s1 r0, D:ShiftLeft s1 r1, U:ShiftLeft s0

Notation: s = shiftKey, r = repeat.

Mechanism (removes the code half of the AND-gate). Both parts are gated by a new
constructor option, windowsShiftHeal, which main.ts sets from isWindowsPlatform(navigator):
1. Second-press recovery. A repeat keydown for ShiftLeft or ShiftRight counts as a genuine
   press when that code is not held and the other Shift is held. A held Shift's own
   auto-repeat is still de-duped.
2. Final-keyup heal. A ShiftLeft or ShiftRight keyup with shiftKey strictly false drops BOTH
   Shift codes. On Windows such a keyup is delivered only when VK_SHIFT goes fully up.
   noVNC ships the same Windows-gated heal. Linux shiftKey semantics on a one-of-two Shift
   release are unverified, so the gate stays.
3. WR-01. drainEdges() supersedes a release latched in the same window as a press for a side
   that is still held at drain time. That window's last edge was a press, so the bat must end
   up. Every consumer (main.ts and the three test mirrors) applies press before release and
   is correct with no change. A side that is not held at drain time still gets both edges,
   and press-then-release is the true order for a tap inside one window.

Purpose: FLIP-01 (every binding answers its key) and GAME-02 (the serve never re-presses a
healed Shift). Bindings, feel constants, the FSM and the Planck adapter are not touched.
Output: the three changes above in FlipperInput, a one-line wiring change in main.ts, and
unit plus keyboard-to-Planck regressions built from the captured sequences.
Out of scope here: the UAT 18 controls-list hint ships in plan 04-13.
</objective>
