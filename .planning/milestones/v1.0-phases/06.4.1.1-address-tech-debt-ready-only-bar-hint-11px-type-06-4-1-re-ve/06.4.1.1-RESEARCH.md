## Summary

All three items are small, and the codebase already has the pieces. The hint signal is `GameSession.activeRestingInZone()`. It is private, pure and allocation-free, and it reads the pooled `world.getBalls()` snapshot through the pure `isRestingInZone`. A public getter that only delegates to it adds no state and cannot perturb a determinism replay. The charge-flicker question in the D-01 discretion clause is answered by the code: the plunger has no body, and `PlungerController.update()` touches only `heldSteps` and `charge`. The world is written only by the release impulse, so a ball resting on the plunger stays at rest for the whole hold. Use the plain rest test; `charging || resting` is not needed.

`HudView` already has an attribute-sink pattern (`bestAttr` and `data-new`) and per-line diffing on change. The hint becomes a sixth optional constructor sink: an `AttrSink` on `<p id="hud-hint">`. HudView sets `data-ready="true"` only when `state === "playing"`, `code === "none"` and `src.isBallOnPlunger()`, and writes only when that boolean changes. The CSS defaults the bar hint to `visibility: hidden` and shows it on `[data-ready="true"]`. That deletes the `:not(:empty) +` coupling (UI-REVIEW fix #3). The 11 to 12 px change touches three declarations. None of the three sets the side panel's width: `.hud-label` is 5 glyphs, `.hud-controls-note` has `contain: inline-size`, and `.hud-bonus-heading` sits in the separate overlay. So the analysis predicts no change to the panel width or the side/bar switch point; the UAT still measures them (D-07).

### Pattern 1: Read-only delegating getter (sim)
**What:** A public getter beside the other `is*` getters that calls the private rest test.
**Evidence:** [VERIFIED: src/game/game-session.ts:677-686]
```ts
  /** Whether the ball in play is resting in the plunger zone (false with no ball). */
  private activeRestingInZone(): boolean {
    if (this.active === NO_BALL) return false;
    const balls = this.world.getBalls();
    for (let i = 0; i < balls.length; i++) {
      const b = balls[i];
      if (b && b.id === this.active) return isRestingInZone(b, PLUNGER_ZONE);
    }
    return false;
  }
```
`isRestingInZone` is pure [VERIFIED: src/control/plunger-controller.ts:78-82]:
```ts
export function isRestingInZone(ball: BallState, zone: PlungerZone): boolean {
  const inZone =
    ball.x >= zone.minX && ball.x <= zone.maxX && ball.y >= zone.minY && ball.y <= zone.maxY;
  return inZone && Math.hypot(ball.vx, ball.vy) < PLUNGER_REST_SPEED_EPS;
}
```
with `export const PLUNGER_REST_SPEED_EPS = 0.05;` [VERIFIED: plunger-controller.ts:57]. Zone: `export const PLUNGER_ZONE = { minX: CHUTE_X, maxX: WIDTH_M, minY: 5.6, maxY: HEIGHT_M, } as const;` [VERIFIED: src/table/spec.ts:219-224]. `getBalls()` returns the pooled array with no side effect: `getBalls(): readonly BallState[] { return this.ballPool; }` [VERIFIED: src/physics/planck-world.ts:804-806].

Recommended code (name: `isBallOnPlunger`, matching `isWarning`, `isLive`, `isNewBest`):
```ts
  /**
   * Whether the ball in play rests on the plunger: inside PLUNGER_ZONE and
   * below PLUNGER_REST_SPEED_EPS (the shared isRestingInZone test); false with
   * no ball. Read-only; the bar hint reads it (06.4.1.1 D-01, D-02).
   */
  isBallOnPlunger(): boolean {
    return this.activeRestingInZone();
  }
```
Do NOT add the tick's previous-step-idle guard (game-session.ts:594-603): it exists only for the skill-shot reopen on the release step.

### Anti-Patterns to Avoid
- **Skill-shot phase as the signal.** It is `frozen` during travel and `off` after resolution (D-02).
- **`display: none` toggling.** It changes the bar height and moves the canvas (06.4.1 truth 2).
- **Writing the attribute every frame.** It breaks the T-6-11 write-on-change invariant; diff it.
- **Any `getBoundingClientRect` / `offset*` read for the hint.** `apply-view.test.ts` requires exactly 2 layout reads, both inside `applyView` [VERIFIED: src/sandbox/apply-view.test.ts:50-56].
- **Putting the flag on `#sandbox` as a `data-hud` value.** `attributeViolations` treats every `#sandbox[data-hud="..."]` CSS value as one main.ts must set [VERIFIED: apply-view.test.ts:74-85]. A different attribute name would pass, but the hint `<p>` keeps the state local.
- **Defense-in-depth that keeps the `:empty` rule.** D-03 says it is replaced. Keeping it re-creates the coupling the UI review flagged.
