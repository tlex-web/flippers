<decisions>
There is no CONTEXT.md: the user chose "Continue without context" and delegated the narrow-viewport layout
to research and planning. The user judges it at the 06.4-04 UAT. Planner choices, each stated so the
UAT can overrule it:
- Layout: "side when it clears, top bar when it doesn't" (RESEARCH Summary and Patterns 1-3). A width-only
  media query is rejected because overlap depends on `vw - 0.536 vh`: 1080x1080 overlaps and 1024x768 does not.
- Assumption A3: in bar mode the controls list (except the Mute row) and the Windows note are hidden.
  Phones and tablets have no keyboard, and a narrow desktop window still shows "PRESS ENTER TO START" and the
  Mute key. The user can widen the window to see the full list.
- Assumption A4: in bar mode the `#hud-diag` dev readout is hidden. It is aria-hidden, and 04-UI-REVIEW
  suggested hiding it outside dev. At 768 it would otherwise sit over the table's bottom-left.
- Open question 1: the bar is full width (minus 8 px margins), so its height never depends on the canvas
  size. If the UAT asks for a table-width bar, the follow-up is `max-width: 560px; align-self: center`.
- Planner correction to RESEARCH Pitfall 1: ball and best are not always mutually exclusive. In attract
  with no stored best (best 0), both `ballText` and `bestText` are "", so a shared cell would collapse and
  the bar would grow about 5 px on Enter. In bar mode, `.hud-ball` and `.hud-best` get `line-height: 1.25`
  plus `min-height: 1.25em`, and `.hud-status` gets `line-height: 1.2` to match its existing
  `min-height: 1.2em`. Every row then keeps one height whether it is empty or not.
- Out of scope (adjacent debt, do not fix): the 11 px type (`.hud-label`, the note, the bonus heading).
  On-screen touch controls are also out of scope.
- `?debug=1` uses `DebugRenderer.resize(world)` and never calls applyView, so it keeps the side layout.
  That is acceptable for a dev mode. Say so in the main.ts header.
- Use `setAttribute`, not `dataset`, to match the HUD's attribute-sink idiom (RESEARCH Pattern 2).
- Layout reads happen only inside applyView, which runs on boot, on resize and on a dpr change, never in
  the rAF frame (T-06.4-02).
</decisions>
