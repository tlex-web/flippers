# Phase 06.4 Plan 01: Narrow-Viewport HUD Bar Summary

**Measured side/bar HUD switch: applyView keeps the side panel only when the fitted canvas clears it, otherwise sets data-hud="bar" and fits the table under a constant-height 3-row CSS-grid bar (score, ball/high score, Mute, status).**

## Performance

- **Duration:** ~10 min
- **Started:** 2026-11-24T16:47:10Z
- **Completed:** 2026-11-24T16:57:20Z
- **Tasks:** 2 (Task 1 tracer, Task 2 expansion)
- **Files modified:** 5 (1 created)

## Accomplishments
- `sideHudClears` / `heightUnderBar` plus `HUD_SIDE_GAP_CSS` (16) and `HUD_BAR_GAP_CSS` (8) in `src/render/view-transform.ts`, pure and unit-tested at six real viewports and over a 57 x 33 viewport grid.
- `applyView` in `src/sandbox/main.ts` measures the panel in side form, flips `#sandbox` to `data-hud="bar"` when it would cover the canvas, and fits the table to the height under the measured bar. Exactly two layout reads, both inside applyView. Boot call, resize listener and dpr re-arm unchanged.
- `index.html` bar CSS: column flex with an 8 px gap, the HUD in normal flow above the canvas (`order: -1`), a 3-row grid (label/aux, score/mute, status/status), with row heights held constant in every game state. Bar mode hides the keyboard list except Mute, the Windows note and the dev readout. Globally, `#stage { flex: none }` and `#sandbox { min-height: 100dvh }`. No markup change, no media query.
- Perceptually: at wide windows nothing moves. At narrow windows the HUD becomes a strip across the top (SCORE label with BALL n / 3 or HIGH SCORE on the right, the big score with the M key and MUTED marker on the right, the magenta status line below), and the table sits 8 px under it, centered. At 375x812 the table keeps its full width-bound size.
