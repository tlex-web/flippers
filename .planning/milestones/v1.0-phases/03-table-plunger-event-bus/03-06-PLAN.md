<objective>
Turn the pooled event drain into the typed, one-way collision bus that Phases 4 and 5
plug into. Every contact names the ball and the spec element it touched, sensors are
included, and the result fans out once per fixed step to registered listeners in a
fixed order.

Purpose: SC#4 asks for a typed collision event on a one-way bus for every ball-vs-element
contact, with ids from the one spec. The router preserves every hard-won property (zero
per-step allocation, one-way flow, one deterministic batch per simulated step) and adds
the one missing thing, multiple independent consumers. The bus is proven wired with a
single demo consumer; no downstream rules are pulled forward.

Output: the evolved event model with normalization, the sensor begin-contact path, the
onPostStep loop seam, CollisionRouter, proofs, and the sandbox wired with one logging
consumer.
</objective>
